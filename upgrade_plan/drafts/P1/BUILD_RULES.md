The master reads it only when designing or reviewing a design.
LEVERS: primary lever from the PATTERNS.md DESIGN families, at least 40 percent of positive test weight, firing in most hidden inputs, lost by the careful exact program written from the shipped files only (until CR2). Misread rule levers allowed under CR7 (one clear deciding sentence, many tempting records); the other paused stated rule kinds stay paused until the lever audit (T3). Carrier variation is a valid source (D2, T4). Bounded induction counts under D1 only when the finite family is stated or shown (T5). Timeout lever only an extra unless Ayush says so (CR1); a size bound may be stated for it (R30). Holes: case by case with Ayush (T11, Q127).
HIDING: a shipped instance may hide a case, never the rule: every hidden branch has its sentence in the docs (T7). Docs never announce a lever: no "note that", no trap list, no method word, no rule count (T9).
DESIGN.md: every lever names the oracle branch, the careful program branch and a saved input where they differ (T10). DESIGN READY needs a predicted final under the gate minus design_margin (settings.json; under 35 today) (T20).
GRADING: every task states the exact bar sentence; tests compare whole documents per hidden run (T12). Never grade a key, field or value form the shipped contract does not name (T13). The instruction states the exact command the tests run (T14). Nothing in environment/ shows the answer for a graded document; the oracle never contradicts the contract (T15).
INSTRUCTION: every criterion traces to an instruction sentence that asks for the output, and that sentence never names the trap, the probe or the method (T16), except conduct criteria (Q130). A worked example uses invented toy values, never a graded figure; when one is graded, the instruction asks for it (T17). Rules of engagement are always stated in a file the agent reads (T18). Every instruction keeps the finish time sentence; no effort cap (T19).
RUBRIC: one code quality criterion when the agent writes code: "a Python reviewer would accept as maintainable, judged on its names, function structure and error handling", conduct label, w1 to 3, the oracle meets it; best tied to an instruction sentence (T41, Q130). A what if figure criterion only when the instruction asks for that figure, at most 6, weight at most 3 each (T42). Honesty negative minus 3 in every judge.
LIMITS: time limit at least 4x the reference time (settings.json) (T43). 0 differences over 2,000 variants: report to Ayush, never park on its own (T44). Blinds before QC are not required; a blind is a diagnostic only (T45). Oracle runs from settings.json: 3, 2 in auto mode with the rest owed before push, 5 once in the final QC before ship (T46).
QC FIXES: fix map: pass QC as teammates do with the right wording, keep traps hidden from the solving agent, keep the hardening, raise no new findings (Q125). No fix softens a lever just to pass QC unless Ayush says so for that finding; a real defect is always fixed: the shipped docs decide the value in one sentence and the hardness is rebuilt in a valid form (T22, Q126).
QC FIX STEPS (R8 to R14, R17): never paste QC "Fix:" text as the direction; never move an assert into an existing check or weight onto a conduct criterion; never delete a clause or grader without naming what grades the rest; recheck every touched check; rerun the vacuity probe; regenerate docs and TRUTH.md last, by script; byte diff tests/ before and after; a finding on unchanged lines that passed before is noise, kept with diff evidence.
