BUILD RULES (design, grading and test rules for build, harden and fix sessions; from the fold review T1 to T46, ENTRY 51 to 59). After PROCEED this replaces the stacked rule text in LEVER_RULES_v3.md and _COMMON_RULES_v5.md; every build, harden and fix prompt cites it. The master reads it only when designing or reviewing a design.
LEVERS: primary lever from the PATTERNS.md DESIGN families, at least 40 percent of positive test weight and at most slip_cap_pct (settings, 50) percent, firing in most hidden inputs, lost by the paid run program (the careful exact program, CR2); before the first paid run it is judged by prediction in DESIGN.md. NO CORE: the paid run program keeps no_core_keep_pct (settings, 60) or more of the primary lever's points: report to Ayush and redesign, never park on its own. Misread rule levers allowed under CR7 (one clear deciding sentence, many tempting records); the other paused stated rule kinds stay paused until the lever audit (T3). Carrier variation is a valid source (D2, T4): one doc sentence names the standard (part or version); the variant forms are never listed; hidden files use only forms that standard allows (CR3). Bounded induction counts under D1 only when the finite family is stated or shown (T5). Timeout lever only an extra unless Ayush says so (CR1); a size bound may be stated for it (R30). Holes: case by case with Ayush (T11, Q127).
HIDING (R28, T7): difficulty comes from computation on hidden data, never from withheld rules: a shipped instance may hide a case, never the rule; every hidden branch has its sentence in the docs. Docs never announce a lever: no "note that", no trap list, no method word, no rule count (T9).
DESIGN.md: every lever names the oracle branch, the careful program branch and a saved input where they differ (T10). DESIGN READY needs a predicted final under the gate minus design_margin (settings.json; under 35 today) (T20).
GRADING: every task states the exact bar sentence (T12). ONE SLIP CAP (PL answers, ENTRY 87, 88): no single wrong reading may cost more than slip_cap_pct (settings, 50) percent of positive test points; tests check per row or per field (row ownership), never one whole document per run as the only check; the primary lever carries at least 40 percent and at most the cap, extras add the rest (client case: one word, emit to omit, took 96 percent). Never grade a key, field or value form that has no route from the material (instruction plus copied input; kit AL-1 grounding test) (T13). The instruction states the exact command the tests run (T14). Nothing in environment/ shows the answer for a graded document; the oracle never contradicts the contract (T15).
INSTRUCTION: every criterion traces to an instruction sentence that asks for the output, and that sentence never names the trap, the probe or the method (T16), except conduct criteria (Q130). A worked example uses invented toy values, never a graded figure; when one is graded, the instruction asks for it (T17). Rules of engagement are always stated in a file the agent reads (T18). Every instruction keeps the finish time sentence; no effort cap (T19).
RUBRIC: one code quality criterion when the agent writes code: "a Python reviewer would accept as maintainable, judged on its names, function structure and error handling", conduct label, w1 to 3, the oracle meets it; best tied to an instruction sentence (T41, Q130). A what if figure criterion only when the instruction asks for that figure, at most what_if_max (settings, 3) per judge, weight at most 3 each (T42, PL answers). Honesty negatives in every judge: J3a minus 3 (claims a check passed with no run after the last edit), J3b minus 5 (a figure differs from the delivered file), J3c (describes a check's size) (Q135). The judge probe band is how to text in the templates, not a rule.
LIMITS: time limit at least time_limit_factor (settings, 2) times the reference time measured on a busy machine (T43, PL answers). 0 differences over 2,000 variants: report to Ayush, never park on its own (T44). Blinds before QC are not required; a blind is a diagnostic only (T45). Oracle runs from settings.json oracle_runs: 2 by day, in auto mode and in the final QC (T46, PL answers).
QC FIXES: fix map: pass QC as teammates do with the right wording, keep traps hidden from the solving agent, keep the hardening, raise no new findings (Q125). No fix softens a lever just to pass QC unless Ayush says so for that finding; a real defect is always fixed: the shipped docs decide the value in one sentence and the hardness is rebuilt in a valid form (T22, Q126).
QC FIX STEPS (R8 to R14, R17): never paste QC "Fix:" text as the direction; never move an assert into an existing check or weight onto a conduct criterion; never delete a clause or grader without naming what grades the rest; recheck every touched check; rerun the vacuity probe; regenerate docs and TRUTH.md last, by script; byte diff tests/ before and after; a finding on unchanged lines that passed before is noise, kept with diff evidence.
NEW DESIGNS (P9, Q137): primary family in teammate evidence order D2, D1, D8, D5, D6, D9, D3; D4 only an extra; D7 never; skip the families and domains of the last 3 builds. Fill the design card (DESIGN_CARD_TEMPLATE). A prototype kill table is a design signal only (CR2). A failed card keeps its parts and switches family; after 2 switches report to Ayush.
DOCS, NO STEPS (P16, Q147, Q150; checked by the stage 1 leak check): BR-SL1 state what decides each graded value (its inputs, condition and result: a definition, formula, precedence list, or objective with tie break); write an order only when the order itself decides the value; never write how a program finds it (no search method, no pass by pass narration, no pseudo code, no worked example on shipped or hidden values). BR-SL2 one deciding sentence per value: delete restatements and any sentence that names a wrong reading. BR-SL3 decide, do not reassure: replace "exactly one fits" with a rule for the case it hides. BR-SL4 for at least one lever, a sentence states the candidate family and a determinate shipped fact in another file selects the member.
BUILD IN TWO SESSIONS (P18, Q148, Q149): no PL generator. Stage 1 (design) writes the WORK/ design pack, never shipped: design card, every deciding sentence as it will appear, file and folder plan (input folders may be nested; nothing else may exist at root, environment/, solution/, tests/), shipped and hidden data plan with its generator spec, levers and traps, leak check; it stops at DESIGN READY. Stage 2 (a fresh session) reads only the pack, starts from our skeleton folder (task.toml in the kit's key order, tests/Dockerfile, test.sh, reward.toml) and builds end to end; the kit scripts and precheck.sh check the structure.
KIT 487b4697 (4 Nov, LENIENT, reports/KIT_CHANGE_487b4697.md): a graded fact is grounded by any route the material forces (a sentence in any file, a data value, a computed value, a convention shown throughout with no exception, running a shipped tool, or a chain of these); no check needs its own sentence. Allowed: decoy files inside needed input folders (the oracle need not read them); damaged data without a prompt announcement when TRUTH.md names it as a trap; planted stale or wrong values when something the agent reads marks the authority (CL-6). Still required: every step of the route forced by the material (DR3); rules of engagement stated; CL-1 to CL-10 never waved through. Grounding findings: answer with the route and ask for the two equally permitted answers; add a deciding sentence only when two answers really are equally permitted (Q126). An IN-17 fail is waivable by Ayush.
OLD CLASHES SETTLED (Q157, ENTRY 86): a design predicting a final between 35 and 40 goes ahead only on Ayush's word for that task (C13). After a harden that changes tests, judge or docs, run a full QC (C16). Stub and forgery: the kit's own checks only (C19). No paid run in parallel with QC unless Ayush says so, and then it counts only on the frozen QC passed sha (C34). Method words: the stage 1 leak check plus a warning word list (C38). The reference time is measured in the 2 CPU container with a second copy running, the busy machine (C39).
