## Score conventions
- Tests channel only, unless a real judged run happened (there is no OPENAI_API_KEY here). Label every score "tests-only".
- Gate: tests < 85, rubric < 85, final < 40 (settings.json) on 1 valid run of the frozen QC-passed bytes before push. Final = (tests + rubric)/2. Never rerun the same bytes after a miss. Design for a predicted final under 35.
- Counts: tests and judge criteria each at least the QC minimum (10 tests, 8 criteria; FAIL below); soft cap 70, hard cap 100 (settings.json). A kit count warn is recorded with the count, never merged away. No single wrong reading may cost more than 50 percent of positive test points: tests check per row or per field, never one whole document per run as the only check (BUILD_RULES GRADING).
- QC pass (RULES_IN_FORCE QC PASS): one complete QC pass; every real fail fixed; a fail is closed as a false positive only when it is truly false against the check text, with a note; an IN-17 fail Ayush may waive; warns fixed except the test and rubric count warns; minors: the master proposes keep or fix per minor and Ayush decides (minor_decisions.jsonl). Every finding is judged on its merits. Then the QL runs a full QC.
- Hardness is measured only by the paid run on the frozen QC-passed bytes, scored per check by `tools/loss.py`. A blind read is a diagnostic only. No task is parked except on Ayush's word; 0 differences over 2,000 variants is reported to Ayush, never parked.
- Order (RULES_IN_FORCE ORDER): design (stop at DESIGN READY for Ayush's go; in auto mode the master checks it and writes the go file), build (precheck self-checks), full QC until it passes, QL QC when the QL reports, freeze, 1 paid run on the frozen bytes. No hardening between QC pass and paid run; after a gate miss, harden from what the run got wrong with the fix map, QC again, 1 new paid run. A missed gate is never re-run on the same bytes (decision 6): the same bytes spread about ±17.5 tests and ±20 final (sentinel attempts 5 and 6), so a re-run measures luck. `harbor trials regrade` is a diagnostic only, never push evidence. [v3.7 regrade exception, Ayush 28 Oct Q1] A regrade counts as push evidence only when the edit touches judge files only (no tests/, no instruction, no environment), the run was valid, Ayush wrote OK for this regrade (verbatim in decisions.jsonl), and the regraded run is repackaged with `master_chat_tasks/tools/repackage_one.py` (A4). Otherwise diagnostic only, never packaged.
- Packaging integrity: a pushed bundle is packaged from exactly the frozen bytes the gate run used; Output_RFP `tests/` equals the frozen `tests/`, and the scores come from that run (scripts/package_rfp_bundles.py copies scores without recomputing, line 73; never package a regrade, except under the v3.7 regrade exception above).
- Baselines: a score from a run with a grader error (permission, crash, timeout, missing file) is never a baseline. Only `valid: true` lines of `master_chat_tasks/registry/scores.jsonl` count.
