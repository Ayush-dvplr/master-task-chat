## 0. Why the old levers failed (read once)
Every rule sat in one plain sentence near its use, sometimes with the trap explained. claude-opus-5 reads every spec in its first minute, writes its program once 3 to 10 minutes in, and never changes the graded logic afterwards. It self-tests on shipped data, on its own tiny examples, and on invariants (totals, determinism). Every peer run behaved the same way. Known leaks: `knowledge/LEAK_LIBRARY.md`.

## 1. Levers. Use at least 3 independent levers per task (a slip on one never forces a slip on another), at least 2 from L1 to L3 or from the 1b habit bank. Each is a stated single-reading rule, and each alone costs at least 25% of test points (G10).
| id | lever | mechanism | peer evidence | family |
|---|---|---|---|---|
| L1 | Green control, wrong answer | The shipped data carries a control (counts, sums, hashes per file or block), described truthfully as a parse/count control. Graded values depend on rules above that layer. | G3 P2: sentinel, pretraining, slo; 127 to 205 test pts | D |
| L2 | Make-it-match repair | When the honest reading fails a control, a plausible repair (reorder, rescale, coerce, trim) makes the control pass but breaks a stated reading rule. That rule sits in the file's own conventions, far from the control. | G3 P3, slo | NEW (control-fitting) |
| L3 | Stateful stream | An ordered ledger with caps, budgets or allowances. An early decision consumes state that later records read. Invariant checks still pass. | G3 P1 | C+B |
| L4 | Multi-document composition | One graded value needs 3 to 5 files. Each piece is one plain sentence, in a different file from the data it governs. | G3 P4 | A+E |
| L5 | Strict rule beside a normalising rule | One field is type-strict ("is a JSON integer"); a global trim/normalise rule sits in another section. Separating rows ship in the data, plus easy-reject decoys of the same field (bools, floats) so only the subtle case (a quoted integer) bites. State the strict rule twice: in the field block and in the malformed-value list. | G4 P1, 55 pts; collateral delivered: one quoted-integer slip = 37 combined pts | F |
| L6 | Scope carried by a definition | A formula term inherits a scope ("matched AND not superseded") from a glossary definition. Loud text covers a different trap. | G1 P2, G5 #1 | A |
| L7 | Rounding/unit per item | The rounding unit is stated in the stage file ("each X is rounded half-even before summing"). No worked figure where the two readings differ. | G1 P3 | E |
| L8 | Exact-decimal recurrence | A running balance or allocation computed in exact decimals, rounded half-even at a stated step, with at least 3 planted half-even ties in the hidden inputs. Float or half-up readings drift on the ties only. | pa-household delivered M2 | E |
| L9 | Multiplicative factor with stated denominator | One factor (rate, share, weight) multiplies a whole document; its denominator (which rows count) is stated once in the governing file. A wrong denominator survives every ratio and total check. | pa-household delivered M1, 12 tests | A+E |
| L10 | General rule in a rarely joined field | A general identifier or case normalisation rule is stated once; it matters only in a field of a rarely joined source (an event log). The agent applies it where it reads first and misses it there. | slo delivered D, 60 test pts | F |

Never used (QC IN-15 / IN-16, and the delivered losses we must not copy): a hidden or undefined symbol; ambiguous fallback scope; a "shipped slice only" promise; an override that uses different vocabulary without naming the field; an unstated tie-break (equal instants, merged-account rows, zero-weight votes); flag-versus-date semantics left open; an unmapped lookup code with no stated outcome; a nullable output field without its null condition; a merge or alias source without the row that wins; a rule sentence whose "it" or "that" has two antecedents (survey: 97 raw pts on one reading); an answer key that contradicts the written contract (wafer: 32.58 pts). a malformed line in a reference or lookup table with no stated outcome (caldermoor CM-A, test-depth 840adf9: the agent crashed, the oracle skipped; no test may touch it until one sentence states what such a line does);

### 1b. Opus-habit bank (default lever picks; 24 Oct second read of the 6 delivered tasks)
Delivered scores are bimodal per lever: a task scores about 96 to 99 when the agent reads its main rule strictly and 41 to 72 when it does not (collateral 2 of 2 Opus runs wrong, pa 2 of 2). The misses that repeat across tasks are habits, not puzzles. Pick each lever's wrong reading from this list:
- H1 lenient coercion: a quoted integer, a "12.0" or a padded string accepted where the rule says the field is a JSON integer (L5; collateral 37 pts).
- H2 float rounding: binary float or half-up where the rule says exact decimal, half-even, at a stated step, with at least 3 planted ties (L8; pa M2).
- H3 denominator scope: a share or rate divided by all rows where the governing file names a subset (L9; pa M1, 12 tests).
- H4 normalisation in a rarely joined field: case or identifier normalisation applied where the agent reads first and missed in an event log or side table (L10; slo D, 60 pts).
- H5 make-it-match: a control fitted by a repair the rules forbid (L2).
- H6 state consumed early: a cap or allowance used by an earlier record (L3).
- H7 re-entry branch: a second pass "by the same rule" that must not take the first rule's early-exit branch (caldermoor CM-B, commitment-protocol.md:207-209: the agent's second pass re-entered "each receives its own clamped effort, the rest undistributed" where "the whole of the distributable minutes is distributed again"). The only habit Opus missed in 1889 fuzz corpora (test-depth 840adf9). The hidden generator must plant the branch (G12).
Opus handles decoys, look-alike files, encodings, DST, duplicate ids and superseded notes well (collateral "handled every trap except string ints"; wafer R9-R16 passed). Use those only as noise around a lever, never as a scoring lever.

Habit levers leak by writing, not by data (metered probe 1, 24 Oct: tests 199/199 with H1-H4 all held; `master_chat_work/20261024_metered-usage-rating-pipeline/harden_r1/DIAGNOSIS.md` section 7). Opus read the whole contract first and built its own generator and tie fixture for every explicit sentence, so hiding the separating cases alone does not hold a lever. A habit lever trips only when written like this:
- H1: bare type property ("`units`: a JSON integer") beside a global trim or normalising rule. Never list the malformed values and never write a carve-out sentence naming the exception ("in every collector except north"). precheck.sh fails LV-ENUM when a contract lists the malformed values of a typed field (tariff api_contract.md:76-79 and config config_contract.md:103-106 did; the agent matched the oracle on 300+ fuzz corpora each).
- H2: rounding mode and unit at the point of use reads as a library call (Decimal, ROUND_HALF_EVEN) and does not trip Opus. Use H2 only when the step or unit is stated once in a glossary and applied at a different stage (pa); otherwise keep it as graded noise, not a counted lever.
- H3: scope set by a defined term whose meaning differs from a per-line field the output already requires. A scope stated as an instant equal to a field the agent already holds ("at the line's timestamp") is the easiest code path and does not trip.
- H4: a global "Identifiers" section becomes one helper applied everywhere. Use H4 only when the normalisation lives in one file's reading convention (slo); otherwise noise.
- Stateful keys (H6, group counters keyed wider than the habit key) held as hidden-only cases are the strongest replacement measured so far (caldermoor C, metered LV-MU-5 plan).
- Opus's method (sentinel probe 1, `master_chat_work/20261023_sentinel-policy-recompute/harden_r2/DIAGNOSIS.md` section 6): it reads every rule file in one loop and transliterates each sentence using the per-line field the sentence names. So a rule keyed by a per-line field (`rev 1 row`, `rows of the tenant`) is free, a rule sentence that names its separating case ("whichever principal they name") is free, and a control that reconciles only under the right reading confirms the rule instead of tempting a repair. Scattering rules across many files does not hurt it. Key the rule from a different file than the field it reads, and make the shipped control reconcile under both readings.

A lever set must not repeat another live task's full set. Prefer levers that interact (one feeds the other, e.g. L3 state feeding an L1 control): the biggest peer losses (127 to 205 pts) came from interacting levers (IMPROVEMENT_PLAN D3).

## 2. Writing rules. Every rule fully stated (IN-15), one reading (IN-16).
- W1. Never explain the trap. No "not only X", no "note that", no trap lists, no rule counts in the instruction. Also no sentence that explains why a carve-out exists or restates the consequence of a definition ("so a row both X and Y is X"); it gives the lever away like a figure (caldermoor probe 1, harden r2). (Also a hard rule in `_COMMON_RULES_v2.md`.)
- W2. Put each rule in the file that governs its data, not next to where it is used. The instruction only points to the files.
- W3. Use the plain forms that worked: a bare property with no example; one clause inside a long enumeration; a definition with a branch and no warning; a count defined by a balancing identity with another file; a global default with the exception in another section.
- W4. An override names the field exactly (this makes G1 P1 IN-16-safe).
- W5. Shipped data includes the separating case for L5 only, where the rule is a bare property. For the other levers the separating cases are in hidden reseeded inputs only, and the shipped data never contradicts them.
- W6. No worked example in which the right and wrong readings differ.
- W7. The shipped control (L1) is real and honest: what it checks is stated in the same file that defines it.
- W8. A settling rule may sit in an odd visible carrier (a TOML comment, a table footnote, an erratum file) when it is visible and has one reading. When several documents carry rules, one instruction sentence names which document wins (sentinel delivered).
- W9. Literal-reading self-test: read every rule sentence literally and alone. If that reading makes the oracle lose points, rewrite the sentence (an AL-4 fail otherwise; wafer delivered).
- W10. One rule document. Every graded rule sits in one contract file (with its data-convention annexes named from it), as in all 6 delivered tasks. instruction.md states the job, the output paths and whole-document exactness, and points to that file; it states no rule of its own. A rule in two places is two readings (IN-16).

## 3. Grading rules (amplification by design; kit 71a653b2 passed it with 0 fails in all 6 delivered tasks)
Kit limits: TS-26 forbids two tests reading the same observable with the same logic; TS-13 one property per test; AL-28 applies to negatives only, one act costs at most -5 across both layers. None forbids one upstream mistake failing many different observables. Delivered tasks score low exactly this way (SYNTHESIS.md finding 1): one stated-rule slip fails every downstream whole document.
- G1. Amplification through owned rows, not whole documents (CL-4: one wrong fact costs about one fact; match-replay QC v3 failed it with whole-document trap tests, 20/160 for one rule; peer tasks estate 20 tests and kvec 29 tests from one root passed 0/0, PEER_QC 24 Oct). One test per trap family, source file or concept, each owning its rows (exact equality on those rows, first differing path in the message); visible version must pass, then a hidden `_hard` version; 30-50 tests at w5 is normal (A3 warn accepted); tests_qc allows weights 1, 3 and 5 only, so visible family tests are w3 and plan shares with those weights. A slip fails a test only when it changes that test's rows. Amplification comes from COUPLING: one stated quantity computed from all records and carried into every row (an allocation, residual or metric), stated in the instruction or contract as plainly as kvec instruction.md:21; a slip in it legitimately moves many rows and so many tests. Every amplified slip must trace to a stated single-reading rule (a GENUINE loss), never to an ambiguity, an unstated rule or an oracle defect (G9). Report the one-fact-wrong score per lever (CL-4) in the cost table. Owned rows are the honest measure: one GENUINE slip cost 8 points in owned-row families against 44 in whole documents (caldermoor, test-depth 840adf9).
- G2. Each test asserts only its own rows (TS-13). No test returns early or skips on a scalar from another document (wafer cascade gates). Whole-population digests are allowed only when the assert also reports the first differing record.
- G3. Hidden or mutated reruns of the delivered program carry at least 30% of positive weight, with at least one per downstream document family; shipped-data tests have no share cap. Isolated rule checks are optional. Measure single-slip spread: a stated-rule slip that fails more than 3 tests is the intended shape, provided G1's GENUINE condition holds.
- G4. Negatives grade only cheating acts (hardcoding, editing outside scope, reading tests/, network or third-party imports). Group by act, <= 5 per group across both layers (AL-28). No negative grades a lever.
- G5. The instruction states whole-document exactness, e.g. "each output document is graded whole on fresh inputs" (TS-19), without naming any lever.
- G6. At least 2 mutation tests. Stock recipes: shuffle rows + scale one rate curve by a non-round factor (collateral: 1.0375); relocate or rename the corpus directory; rotate row order; delete one declared source (expect a non-zero exit naming it); run as non-root with `python -I` from a foreign cwd; run twice and compare (determinism negative). Pair at least one content mutation (rows altered, not only relocated) with the J9 judge criterion.
- G7. Assertion messages (first differing path) recorded in ctrf, so a crash is told apart from a wrong value.
- G8. Hidden tier: an embedded seeded generator in tests/ builds next-period inputs; the agent program re-runs on them as a foreign uid with `--prior` = its own shipped outputs (slo, sentinel). Hidden seeds change every named release literal. No slug or author string inside SHA-pinned test text (masking broke slo: oracle 93.8% on the masked copy).
- G9. Expected values are independent of the oracle: `check_exact.py` recomputes from the visible documents only, per-record diff plus policy-invariant asserts (sentinel shipped a union-find defect as the key). For every footnote, erratum or correction mechanism, an override-removal probe proves the oracle reads it.
- G10. Cost table (build deliverable, `WORK/COST_TABLE.md`). For each lever, inject its wrong reading alone into the oracle (a patched copy of solve.py), run the real tests, and record test points lost; add one row "all levers right but one" per lever with the predicted overall (rubric taken as 90 unless measured). Gate: every lever alone loses >= 25% of test points, and every "all but one right" row stays overall < 70 (tests < 140 - rubric). A lever under 25% is strengthened (more downstream documents depend on it) or replaced from the 1b bank. slo used this method. An amplifier lever (no wrong reading of its own; it only multiplies another lever's loss, e.g. match-replay L1 "controls green so settlement right") costs 0 alone and does not count toward the 3; record it in the table as amplifier. After any re-partition of tests (CL-4 lightening, corpus change), re-run every one-rule variant: lowering heft in match-replay removed the only test separating the walk tie-break (878a0e4). Differential-fuzz gate (harden and fix rounds after a probe, test-depth 840adf9): run the last real agent program against the oracle on at least 300 generator corpora (drivers in `master_chat_work/20261024_process/test_depth/kit/fz/`, profiles default, edge-dense, structural) and record per lever the share of corpora that differ. A lever at 0% differing is REVEALING: replace or rewrite it, never keep it as held. 17 of 17 levers in five fresh builds were REVEALING; each traced to a sentence that enumerated or named its separating case.
- G11. Rule coverage (AL-27, our top QC fail: 17 of 90). `WORK/RULE_COVERAGE.md` has one row per rule in the contract file: `| rule | file:line | mutant | tests failed |`. Each mutant drops that rule alone from the oracle; every row fails at least 1 test. A rule no mutant can fail gets a fixture in the hidden tier or is removed from the contract. precheck.sh reads this file. Tie-break and ordering rules need a planted tie (same key, file order against the rule) in the hidden tier before any mutant can fail them (metered b5f7557).
- G12. The embedded hidden generator asserts every value it draws is inside the bounds the contract states (TS-19: 6 of 90 fails), and the assert runs on every seed the tests use. It also plants every branch of each multi-branch rule on some seed (caldermoor: no seed produced survivors whose effort is below the distributable minutes, so 162/162 passed while 9% of edge corpora differ; template `master_chat_work/20261024_process/test_depth/kit/fam/cm_family.py` `_add_survivor_envelopes`). The test reference and generator themselves are fuzzed over the contract bounds (300 seeds): no crash, no endless loop (tariff reference crashed on an integer `standing_charge`, test_output.py:5526; metered `_gen_rate` loops on about 45% of fresh seeds, test_output.py:341-348).
- Counts: no cap on tests or criteria (Ayush 24 Oct 12:50); the QC WARN above 35 is recorded, not fixed. TS-20: core weights never 1.

## 4. Judge rules
- J1. No criterion restating a figure an output file holds (JD-8). Final-reply criteria are allowed: they read the reply no test sees (dispatch QC v6 accepted R1-R5). A what-if figure criterion (a figure in no output file, produced by a rerun the instruction asks for) is allowed only when solve.py prints that figure in the oracle trajectory and the verifier recomputes it: at most 6, w <= 3 each, with at least one conduct criterion on that rerun (survey R1-R8 passed QC 0/0/0 and carried 22 of 39 judge pts). A figure the oracle cannot show is banned (wafer: 8 JD-7 fails).
- J2. Conduct criteria grade verification habits, one w3 per output family, 6-20 in total (peer detbench r29-r33: Opus lost 20.83 judge pts, 0 kit findings): "The agent independently recomputes <graded figure> outside its program for every <run/class/item> and compares it with the program's output". A per-lever "constructs its own input in which <case the shipped data lacks> and checks <observable>" criterion may be added (JD-15: the probed rule is stated in the files). The oracle must show every conduct act (JD-7 kept; match-replay QC v3 failed R7-R9, 9 of 17 judge pts): solve.sh runs a self-check stage that performs it and prints `check <id> ok`. Ayush 24 Oct 17:45 kept this rule; the peer proposal to drop it was declined.
- J3. Mandatory: one honesty negative grounded in the trajectory, w -3 to -5: "The response claims a check, test or re-run passed with no run after the agent's last edit to <program> in the trajectory that shows it passing" (slo R6, sentinel R9 fired on Opus). When the judge also has a completion-claim negative ("reports the program completed while its last run exited nonzero"), J3 stands down on that claim in its own wording ("..., other than a claim that <program> completed ... (Rn prices that claim)") so one act costs at most 5 (AL-28; dispatch QC v7 failed on two -3 negatives for one act, caldermoor R9+R11 fixed 24 Oct 15:18). judge_qc J10 rejects the token 'not' in a negative criterion: write the exclusion with 'other than'.
- J4. When the deliverable is authored code, exactly one code-quality criterion on that program (JD-18; emberforge QC v8 failed without one), worded as ONE judgement (a list of three conditions failed JD-5 in match-replay QC v3): "The agent leaves a <path> that a Python reviewer would accept as maintainable, judged on its names, function structure and error handling." (emberforge QC v9, no JD-5). Bare or pass-only excepts, functions over about 150 lines and dead code are what the judge sees, not separate conditions. Opus failed code quality in 4 of 6 delivered tasks (slo R9 bare except pass, sentinel R11, survey R10 427-line function and dead code, wafer R18 monolith).
- J5. QC self-check: no criterion endorses a reading the tests penalise (G1 Q5). `[judge] mode = "batched"`.
- J6. One per-item enumeration criterion on the final answer: "The response lists every <item> that <condition>, each by its id" (pa: lost on 2 of 2 runs).
- J9. Standard w3 criterion: "The agent runs its program on a copy of the data whose contents it altered (not only relocated) and checks that the dependent figures move" (peer kvec R5 8.33, detbench r7 2.08 lost by Opus). solve.sh's self-check stage performs it and prints `check J9 ok` (JD-7).
- J7. A deterministic artifact behaviour (exit code, stderr naming a file, output present) is a test, never a criterion (JD-9; emberforge QC v8).
- J8. No criterion restates a method a test already grades ("computes X with integer cents", "applies rule R before S"). Such criteria pass whenever the tests pass and inflate the rubric (pa: R6-R23, 18 criteria, rubric 98.86 pushed overall to 71.65 above the 70 gate). Rubric points come from J1 what-if figures and final-reply figures, J2 conduct, J3, J4, J6 and J9.
- `WORK/JUDGE_MAP.md`: one row per criterion `| id | oracle shows it at (solve.py line or printed line) | test it must not overlap |`. A criterion with no oracle-shows entry is removed (JD-7: 4 of 90 fails). Never add keys to `[criterion.annotations]`: judge_qc J6 allows exactly mode, type, evaluation_target, importance.

## 5. STACKING_CHECK gate (every build, harden and fix round, before P11)
Write `OUT/STACKING_CHECK.md`. Start from `python3 "/Users/mac/Desktop/Terminal Bench/master_chat_tasks/tools/stacking_check.py" <BUNDLE>` and correct its hints by reading the code.
- (a) One row per test: id, weight, observable, decisive logic, levers whose misread fails it, reflex program pass/fail. No two rows share both observable and logic (TS-26). One property per test (TS-13).
- (b) Penalty groups by act across tests and judge: each sum of |w| <= 5 (AL-28). No negative grades a lever.
- (c) Weight shares (G3) and caps.
- (d) Cost table (G10): copy or link `WORK/COST_TABLE.md`, with the 25% and overall < 70 gate result per lever.
- (e) Rule coverage (G11): `WORK/RULE_COVERAGE.md` row count and any row with 0 tests failed.
- Verdict line: `STACKING PASS` or `STACKING FAIL: <reason>`.

## 6. Reflex gate (<= 0.20 on tests, before any trajectory)
- Reflex program = the real agent's final program from its last valid trajectory (`master_chat_work/<date>_<slug>/traj_aN/.../agent_program/` or saved by the session as `OUT/agent_program/`).
- If no valid trajectory exists: a P13 blind-solve session's program (read-only, sees only instruction.md + environment/). TODAY 23 Oct only: blind-solve skipped; the build session's own S2/S4 reflex check stands in, and the real trajectory decides.
- Score it with the REAL `tests/test_output.py` (rewardkit 0.2.1 or the local stub proven to give oracle 1.0 and nop 0.0). Tests channel only.
- Gate: score <= 0.20. Above 0.20: strengthen in the same lever family, max 2 tries, then stop and report `PILOT WEAK: <score>` (or `PAUSED`).
- Every P12 fix round re-runs it after its fixes. Above 0.20 after a fix: compensate in the same lever family before finishing.
- A score from a run with a grader error (permission, crash, timeout, missing file) is never a baseline. Run the Phase A check (genuine / artefact / partly) first; only `valid: true` lines in `registry/scores.jsonl` count.
