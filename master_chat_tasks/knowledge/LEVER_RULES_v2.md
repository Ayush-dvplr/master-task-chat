## 0. Why the old levers failed (read once)
Every rule sat in one plain sentence near its use, sometimes with the trap explained. claude-opus-5 reads every spec in its first minute, writes its program once 3 to 10 minutes in, and never changes the graded logic afterwards. It self-tests on shipped data, on its own tiny examples, and on invariants (totals, determinism). It transliterates ANY explicit rule sentence, not only full procedures, and its self-check reproduces its own reading, so a control that reconciles only under the right reading confirms the rule for it. Known leaks: `knowledge/LEAK_LIBRARY.md`.

25 Oct: the peer losses we envied came mostly from silence (an unstated binding time, an open operand, a second model that also fits), which QC still forbids (05:27). The legal difficulty left is (a) composition and amplification of stated rules on hidden inputs and (b) rules with no sentence that one determinate shipped fact settles (L11). Withholding is the kit's default (01:47 "Withholding is the default and difficulty is the point").

## 0b. The determinate test (05:21-32; also decides IN-17, TS-19, JD-15)
A deliverable-property rule needs no sentence when the shipped input (any directory `environment/Dockerfile` copies) DETERMINES it: the agent can read it off the input, and the input contradicts every wrong reading (05:21 "rather than something the input merely fails to contradict").
- Counts: a present data property (3 of 40 rows carry an empty timestamp, 05:26); a config value (`fiscal_start = "04-01"`, 05:29); an example actually given, for output shape and types (FC:492, 04:95); a listed candidate set; a record that only the right reading reproduces.
- Never counts: silence (every shipped id distinct says nothing about repeats, 05:27); pre-formatted values (they show the width, not the rounding rule, 05:28); a branch that never fires on shipped data; readings that coincide on shipped data; any prohibition or scope rule (05:30, 03:50). These need a stated sentence.
- One file settles one demand (05:32): judge the exact fact the check needs, not the file.
- Rules of engagement (scope, which files may change, tools, procedural order, negatives) are always stated (IN-15 01:45; AL-1 carve-out 05:21). Shape and literals of the output may be settled by a shipped example (05:21 constraint exception, FC:492).
- Every rule settled by evidence gets a row in `WORK/EVIDENCE_MAP.md`: `| rule | test ids | shipped fact file:line | wrong readings it contradicts |` (FC:428 "name either the sentence it enforces or the shipped fact it reads").

## 1. Levers. Use at least 3 independent levers per task (a slip on one never forces a slip on another), at least 2 from L1 to L3, L11 or the 1b habit bank. Each lever is a stated single-reading rule or an L11 evidence rule, and each alone costs at least 25% of test points (G10).

(a) Silence, still forbidden (IN-16 01:46, 05:27): ambiguous fallback scope; a "shipped slice only" promise; an unmapped lookup code with no stated outcome; a rule sentence whose "it" or "that" has two antecedents (survey: 97 raw pts on one reading); an answer key that contradicts the written contract (wafer: 32.58 pts); a malformed line in a reference or lookup table with no stated outcome (caldermoor CM-A, test-depth 840adf9). (b) Allowed ONLY when one shipped fact determines the answer (0b) and EVIDENCE_MAP names it, otherwise forbidden: an undefined symbol (a config value defines it); an override using different vocabulary (a shipped mapping table settles it); a tie-break (equal instants, merged-account rows, zero-weight votes; a shipped separating case, and AL-27 05:38 then needs a planted tie and a mutant); flag-versus-date semantics (a separating record); a nullable output field (a shipped example plus a determinate null condition); a merge or alias source (a determinate register shows the row that wins).

### 1b. Opus-habit bank (default lever picks; 24 Oct second read of the 6 delivered tasks)
Delivered scores are bimodal per lever: about 96 to 99 when the agent reads its main rule strictly and 41 to 72 when it does not. The misses that repeat across tasks are habits, not puzzles. Pick each lever's wrong reading from this list:
- H1 lenient coercion: a quoted integer, a "12.0" or a padded string accepted where the rule says the field is a JSON integer (L5; collateral 37 pts).
- H2 float rounding: binary float or half-up where the rule says exact decimal, half-even, at a stated step, with at least 3 planted ties (L8; pa M2).
- H3 denominator scope: a share or rate divided by all rows where the governing file names a subset (L9; pa M1, 12 tests).
- H4 normalisation in a rarely joined field (L10; slo D, 60 pts).
- H5 make-it-match: a control fitted by a repair the rules forbid (L2).
- H6 state consumed early: a cap or allowance used by an earlier record (L3).
- H7 RETIRED 25 Oct (Ayush decision 3). The second-pass re-share family leaked or was converted in every task that used it (6 tasks); do not plan new levers on it. Existing H7 levers stay only until their task's next round.
Opus handles decoys, look-alike files, encodings, DST, duplicate ids and superseded notes well. Use those only as noise around a lever, never as a scoring lever.

Habit levers leak by writing, not by data (metered probe 1: tests 199/199 with H1-H4 all held). Opus builds its own generator and tie fixture for every explicit sentence. A habit lever trips only when written like this:
- H1: bare type property ("`units`: a JSON integer") beside a global trim or normalising rule. Never list the malformed values and never write a carve-out sentence naming the exception. precheck.sh fails LV-ENUM when a contract lists the malformed values of a typed field.
- H2: only when the step or unit is stated once in a glossary and applied at a different stage (pa); otherwise graded noise.
- H3: scope set by a defined term whose meaning differs from a per-line field the output already requires.
- H4: only when the normalisation lives in one file's reading convention (slo); otherwise noise.
- Stateful keys (H6, group counters keyed wider than the habit key) held as hidden-only cases are the strongest stated lever measured so far.
- Opus's method (sentinel probe 1): it reads every rule file in one loop and transliterates each sentence using the per-line field the sentence names. A rule keyed by a per-line field is free, a rule sentence naming its separating case is free, and a control that reconciles only under the right reading confirms the rule. Key the rule from a different file than the field it reads, and make the shipped control reconcile under both readings.

A lever set must not repeat another live task's full set. Prefer levers that interact (one feeds the other): the biggest peer losses (127 to 205 pts) came from interacting levers.

## 2. Writing rules. Every rule of engagement stated (IN-15); every graded rule has one reading (IN-16), from a sentence or from determinate evidence (0b).
- W1. Never explain the trap. No "not only X", no "note that", no trap lists, no rule counts, no sentence explaining why a carve-out exists or restating the consequence of a definition. QC now fails the same act as IN-17 (01:47): a sentence that announces a property, edge case or branch the shipped input already establishes. Two-condition self-check on every instruction sentence: (1) does it announce something the agent was meant to find? (2) does the shipped input already establish it? Both yes = delete it. Our W1 stays stricter than IN-17: counts and trap lists are banned even when the input does not establish them. Requirements stay: rules of engagement, CL-6 not-authoritative signposts, IN-16 settlers, output shape and literals the input does not carry (DS-25).
- W2. Put each rule in the file that governs its data, not next to where it is used. The instruction need not point at the file (01:45 "need not name the file"); a pointer is optional.
- W3. Use the plain forms that worked: a bare property with no example; one clause inside a long enumeration; a definition with a branch and no warning; a count defined by a balancing identity with another file; a global default with the exception in another section.
- W4. An override names the field exactly.
- W5. Stated levers: shipped data includes the separating case for L5 only; for the others the separating cases are in hidden reseeded inputs only, and the shipped data never contradicts them. L11 inverts this: the shipped input MUST hold one separating witness or the fact is not determinate (05:27, 05:28). Ship a single witness record, never a solved list.
- W6. No worked example in which the right and wrong readings differ, except the single unlabelled L11 witness.
- W7. A shipped control is real and honest, and reconciles under both the right and the wrong reading of every lever (a control that reconciles only under the right reading is a free confirmation).
- W8. A settling rule may sit in an odd visible carrier (a TOML comment, a table footnote, an erratum file) when it is visible and has one reading. When several documents carry rules, one instruction sentence names which document wins.
- W9. Literal-reading self-test: read every rule sentence literally and alone; for L11, read every witness literally and alone. If that reading makes the oracle lose points, rewrite.
- W10. One rule document. Every stated graded rule sits in one contract file (with its data-convention annexes named from it). instruction.md states the job, the output paths and whole-document exactness, and states no rule of its own. Wholesale delegation ("follow contract.md") makes every rule it invokes an AL-2 row (05:33).
- W11. No answer for any graded document is visible to the agent (Ayush decision 5; widens common Never 11): no answer key, golden or sample output, solved list, expected figure, claimed total or "the correct result is" sentence for any graded document, anywhere in `environment/`, even when it agrees with the contract. Allowed: honest controls per W7, and the single unlabelled L11 witness per lever. An output-shape example (FC:492) carries placeholder or out-of-scope values, never values from a graded document.

## 3. Grading rules
Kit limits: TS-26 forbids two tests reading the same observable with the same logic; TS-13 one property per test; AL-28 applies to negatives only, one act costs at most -5 across both layers. CL-4 (FC:491) is exempted by "an instruction that states out loud that only an exact match counts".
- G1. Whole-document exact grading per hidden corpus (Ayush decision 4). Tests may compare each output document whole, exactly, on each hidden corpus, provided instruction.md itself states that only an exact match counts (G5); quote FC:491 "An instruction that states out loud that only an exact match counts has set that bar deliberately" in QC_DEFENCE under CL-4. Report the one-fact-wrong score anyway (FC:491 asks for it). Every amplified slip must trace to a stated single-reading rule or an L11 rule with an EVIDENCE_MAP row (a GENUINE loss), never to an ambiguity, an unstated rule or an oracle defect (G9). No stated core gate yet (R9 not adopted). Owned-row tests per trap family stay allowed and are the fallback when QC still fails CL-4 (match-replay QC v3 failed CL-4 with whole-document trap tests, 20/160 for one rule). A COUPLING quantity (one stated or determinate quantity computed from all records and carried into every row) still multiplies a slip legitimately.
- G2. Each test asserts only its own observable (TS-13). No test returns early or skips on a scalar from another document. Whole-document asserts report the first differing record.
- G3. Hidden or mutated reruns of the delivered program carry at least 30% of positive weight, with at least one per downstream document family; shipped-data tests have no share cap.
- G4. Negatives grade only cheating acts (hardcoding, editing outside scope, reading tests/, network or third-party imports). Group by act, <= 5 per group across both layers (AL-28). No negative grades a lever. Every negative quotes, in QC_DEFENCE, the sentence that states its rule (03:50 carve-out, 05:21: a prohibition is never determinate).
- G5. The instruction states whole-document exactness, e.g. "each output document is graded whole on fresh inputs, and only an exact match counts" (FC:491, TS-19), without naming any lever. Do NOT add "at other scales", "other sizes", "there is no count to check yourself against" or any self-check paragraph ("recompute a second way", "outside the program", "on a copy you changed"): QC needs none of them (01:45 conduct needs no sentence) and they invite the self-check that confirms the agent's own reading (Ayush decision 6).
- G6. At least 2 mutation tests. Stock recipes: shuffle rows + scale one rate curve by a non-round factor; relocate or rename the corpus directory; rotate row order; delete one declared source (expect a non-zero exit naming it); run as non-root with `python -I` from a foreign cwd; run twice and compare. Pair at least one content mutation with the J9 judge criterion.
- G7. Assertion messages (first differing path) recorded in ctrf, so a crash is told apart from a wrong value.
- G8. Hidden tier: an embedded seeded generator in tests/ builds next-period inputs; the agent program re-runs on them as a foreign uid with `--prior` = its own shipped outputs where the task has periods. Hidden seeds change every named release literal. For L11 the generator plants a fresh witness per corpus. No slug or author string inside SHA-pinned test text.
- G9. Expected values are independent of the oracle: `check_exact.py` recomputes from the visible documents only, per-record diff plus policy-invariant asserts. For every footnote, erratum or correction mechanism, an override-removal probe proves the oracle reads it.
- G10. Cost table (`WORK/COST_TABLE.md`). For each lever, inject its wrong reading alone into a patched copy of solve.py, run the real tests, record test points lost; add one "all levers right but one" row per lever with the predicted overall (rubric taken as 90 unless measured). Gate: every lever alone loses >= 25% of test points, and every "all but one right" row stays overall < 70. These are design numbers, not hardness evidence. An amplifier lever (no wrong reading of its own) costs 0 alone and does not count toward the 3. After any re-partition of tests, re-run every one-rule variant. Differential fuzz of an EARLIER agent program against a CHANGED bundle is not evidence of anything (Ayush decision 11); fuzz is allowed only as a diagnostic of the program on the bundle version it was written for, and never decides keep or replace.
- G11. Rule coverage (AL-27, our top QC fail). `WORK/RULE_COVERAGE.md` has one row per AL-2 unit (each promise of instruction.md, plus each delegated rule the delegation invokes, 05:33) and per ordering, precedence or tie-break the shipped input establishes (05:38): `| rule | file:line | mutant | tests failed |`. Each mutant drops that rule alone from the oracle; every row fails at least 1 test. Tie-break and ordering rules need a planted tie in the hidden tier. precheck.sh reads this file.
- G12. The embedded hidden generator asserts every value it draws is inside the bounds the contract states or the input determines (TS-19), on every seed the tests use, and plants every branch of each multi-branch rule on some seed (template `master_chat_work/20261024_process/test_depth/kit/fam/cm_family.py` `_add_survivor_envelopes`). The reference and generator survive 300 seeds over the bounds with no crash or endless loop.
- Counts: no cap on tests or criteria (Ayush 24 Oct 12:50); the QC WARN above 35 is recorded, not fixed. TS-20: core weights never 1.

## 4. Judge rules
- J1. No criterion restating a figure an output file holds (JD-8). Final-reply criteria are allowed. A what-if figure criterion is allowed only when solve.py prints that figure in the oracle trajectory and the verifier recomputes it: at most 6, w <= 3 each, with at least one conduct criterion on that rerun. A figure the oracle cannot show is banned (wafer: 8 JD-7 fails).
- J2. Conduct criteria grade verification habits, one w3 per output family, 6-20 in total: "The agent independently recomputes <graded figure> outside its program for every <run/class/item> and compares it with the program's output". The oracle must show every conduct act (JD-7): solve.sh runs a self-check stage that performs it and prints `check <id> ok`. Never echo the conduct wording in instruction.md (01:45: conduct needs no sentence).
- J3. Mandatory: one honesty negative grounded in the trajectory, w -3 to -5: "The response claims a check, test or re-run passed with no run after the agent's last edit to <program> in the trajectory that shows it passing". When the judge also has a completion-claim negative, J3 stands down on that claim in its own wording ("..., other than a claim that <program> completed ... (Rn prices that claim)") so one act costs at most 5 (AL-28). judge_qc J10 rejects the token 'not' in a negative criterion: write the exclusion with 'other than'.
- J4. When the deliverable is authored code, exactly one code-quality criterion on that program (JD-18), worded as ONE judgement: "The agent leaves a <path> that a Python reviewer would accept as maintainable, judged on its names, function structure and error handling."
- J5. No criterion endorses a reading the tests penalise. `[judge] mode = "batched"`.
- J6. One per-item enumeration criterion on the final answer: "The response lists every <item> that <condition>, each by its id".
- J7. A deterministic artifact behaviour (exit code, stderr naming a file, output present) is a test, never a criterion (JD-9).
- J8. No criterion restates a method a test already grades. Rubric points come from J1, J2, J3, J4, J6 and J9.
- J9. Standard w3 criterion: "The agent runs its program on a copy of the data whose contents it altered (not only relocated) and checks that the dependent figures move". solve.sh's self-check stage performs it and prints `check J9 ok` (JD-7). Never echoed in instruction.md.
- `WORK/JUDGE_MAP.md`: one row per criterion `| id | oracle shows it at | test it must not overlap |`. A criterion with no oracle-shows entry is removed. Never add keys to `[criterion.annotations]` (judge_qc J6 allows exactly mode, type, evaluation_target, importance).

## 5. STACKING_CHECK gate (every build, harden and fix round, before P11)
Write `OUT/STACKING_CHECK.md`. Start from `python3 "/Users/mac/Desktop/Terminal Bench/master_chat_tasks/tools/stacking_check.py" <BUNDLE>` and correct its hints by reading the code.
- (a) One row per test: id, weight, observable, decisive logic, levers whose misread fails it. No two rows share both observable and logic (TS-26). One property per test (TS-13).
- (b) Penalty groups by act across tests and judge: each sum of |w| <= 5 (AL-28). No negative grades a lever.
- (c) Weight shares (G3).
- (d) Cost table (G10) with the 25% and overall < 70 gate result per lever.
- (e) Rule coverage (G11): row count and any row with 0 tests failed.
- (f) EVIDENCE_MAP (0b) and, for L11, UNIQUENESS: every test that grades a rule with no sentence names its shipped fact; every L11 witness has exactly one fitting reading.
- Verdict line: `STACKING PASS` or `STACKING FAIL: <reason>`.

## 6. Probe gate and evidence rules (Ayush decisions 7, 8, 11; replaces the v1 reflex gate)
- Blind read before every probe: 3 fresh P13 blind-solve sessions (each sees only a copy of instruction.md and environment/, writes its program once, self-checks on shipped data, stops). Score each program with the real tests and `tools/loss.py`. A lever counts toward the 3 only when at least 2 of the 3 programs get it wrong. A lever 2 or 3 programs get right is rewritten before the probe is queued; it is never "held".
- Harden decisions rest on 1 real harness run plus that round's blind reads. The final gate (tests < 100, rubric < 100, overall < 70) needs 2 valid runs.
- Before diagnosing any run, diff the run's staged copy and ctrf test ids against the repo bundle (Phase A). A score from a stale or different tree is not a baseline.
- Kill rule (Ayush 26 Oct, replaces 'tests >= 95'): park when the probe's final reward (tests and judge combined, as the harness reports it) is above 70. Tests alone never park a task: delivered peers pass with tests 85-96 and a low judge (Final_Delivery 0b27b9dc 96.5/26, 7e0d8feb 94/33, e13fd332 90/25). Blind reads report a judge estimate next to the tests score: final-answer and output criteria judged from the blind program's outputs and final reply, process criteria counted as passed (upper bound). A round marked LAST is the last; no further harden round on that task.
- "QC deferred" or "QC will decide" is never a pass for IN-16 (Ayush decision 8): every graded question needs its sentence or its EVIDENCE_MAP fact before QC.
- Not evidence: differential fuzz of an old program on a changed bundle; a per-lever claim from one run; oracle-injection numbers presented as agent behaviour.
- A score from a run with a grader error (permission, crash, timeout, missing file) is never a baseline. Only `valid: true` lines in `registry/scores.jsonl` count.
