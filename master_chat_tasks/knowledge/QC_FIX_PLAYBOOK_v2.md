## 0. The idea: pass QC on merit, keep the trap at full strength
"Bypass" here means: satisfy exactly what the rule demands and nothing more. It never means hiding a defect from QC. A dodge fails twice: P11 re-runs blind, the PL re-runs, and the kit treats the dodges themselves as findings (a vague rule fails IN-15, "Vagueness counts against the author" 01:45; a wrong label fails JD-15, "report the label as the defect" 04:92).

What the kit demands, and what it does NOT demand (quote these in KEEP / REBUT lines):
| demands | does not demand |
|---|---|
| every rule of engagement (scope, which files may change, tools, procedural order, negatives) stated in a file the agent can read (IN-15 01:45, AL-1 carve-out 05:21); every deliverable-property rule (formats, literals, conventions, output precedence) stated OR settled by one determinate fact in the copied input, a shipped example included (AL-1 05:21-32, FC:492, 04:95) | the rule in the instruction or beside its use, or a pointer to its file: "you must not ask for the rules to be copied into the prompt", "need not name the file" (01:45); a sentence for a fact the input determines (05:21) |
| one reading for anything graded, shown by all three parts (IN-16) | polished or explicit prose: "Wording you merely find loose, terse or unpolished is not this check"; "If both readings would satisfy every test and every criterion, there is no defect" (01:46) |
| every promise of instruction.md (plus each delegated rule it invokes, 05:33) graded by an input that triggers it, including orderings the input establishes (AL-2, AL-27 05:38) | fewer rules or simpler data |
| the oracle satisfies every criterion (JD-7) | weaker criteria |
| one observable paid once (TS-26, JD-14); one act <= -5 (AL-28, negatives only) | fewer cascading whole-document tests (G1, accepted district-heat v3:185) |
| no answer recoverable from the data (DS-4); no instruction sentence announcing what the input establishes (IN-17 01:47) | explanations, worked examples, hints, rule counts |
| at least 10 checks and 8 criteria, no upper cap (Ayush 24 Oct 12:50); the kit WARN above 35 checks (TS-23, 03:62) is recorded with the count | merging or dropping any check to reach a count |

Fix directions that keep the trap (prefer in this order): (1) fix the oracle or TRUTH.md; (2) add hidden triggering inputs; (3) narrow, re-label or re-scope a criterion or a negative; (4) merge low-value format or presence checks; (4b) for an AL-1 / TS-19 / IN-16 finding on a deliverable property: ship one determinate fact that contradicts the wrong reading (a config value, a separating record, a listed set) and add its EVIDENCE_MAP row, never a solved list or answer (W11); (5) state a missing rule once, neutrally, in the file that governs that data.
Soft directions (never, unless Ayush says so for one finding): delete a rule, move a rule next to its use or into instruction.md, add an example where the readings differ, explain why a reading is wrong, say how many rules there are, loosen a criterion to fit the oracle, drop or merge a check that a lever's wrong reading fails, shrink or simplify hidden data, put the separating row in shipped data (W5 allows L5 only).

## 2. Direction line format (master, P12 `[[FIX_DIRECTIONS]]`)
`<finding id> | FIX / KEEP / REBUT | row <id> | <file:line>: <what to change> -> <to what> | levers: <L>=none/harder/easier ... | compensation: none / <check>`
Rules: one line per finding (❌, 🟡, ⚠️); every FIX names file and change; any lever marked easier carries a compensation; a REBUT quotes the kit line it rests on.
Example (cohort v3, 23 Oct):
- `JD-7 | FIX | row JD-7 | solution/solve.py:48-51: except ValueError: return None -> report the message and re-raise or record it | levers: all none | compensation: none`
- `AL-2/CL-1 | FIX | row AL-2 | instruction.md:7: remove the final-reply figures sentence | levers: all none | compensation: none`
- `AL-27 | FIX | row AL-27 | hidden generator: add rows with a duplicate account_id across both merge sides, and a duplicate of an excluded row, inside stated bounds; assert counts under the earlier step | levers: L2 harder | compensation: none`

## 3. Trap-survival check (every P12 session, and every harden round that touches a QC fix)
1. Before any fix: record for each lever the points lost when the reference plays that lever's wrong reading alone (the single-lever table of STACKING_CHECK (d); variants in `WORK/wrong/` or the harden OUT folder). If no variants exist, write each as a copy of solve.py with exactly that one wrong reading, and measure on the unfixed tests in the same session.
2. After the fixes, on the fixed tests: re-run the same variants.
3. PASS when: every lever still loses at least 90% of its before share of positive points and no lever's separating hidden case was removed. (The reflex score part is retired 24 Oct: reflex programs did not predict real runs; the real probe does.)
4. FAIL: compensate in the same family (section 4), re-measure, at most 2 tries, then stop with `PAUSED: trap <L> <before> -> <after>`.
5. Write a `## Trap survival` table to the fix report: lever, before loss, after loss, ratio, separating cases kept (y/n), verdict.

## 4. Compensation menu (same lever family only)
- L1 green control: one more hidden extract where the control passes and a graded value differs.
- L2 make-it-match: one more hidden row where the plausible repair makes the control pass and breaks the reading rule.
- L3 stateful stream: longer hidden streams with more records reading state an early decision consumed.
- L4 composition: one more file in the chain for an existing graded value (rule stated in that file).
- L5 strict beside normalise: one more value type with a separating row (shipped allowed, W5).
- L6 scope by definition: the scoped term used in one more graded formula.
- L7 rounding per item: more hidden items where per-item and per-total rounding differ.

## 5. After the round
- New QC verdicts on lever-touching rules -> `QC_RULINGS.md` row.
- A fix that softened a lever despite this file -> new NEVER entry here (v2) and a lessons.jsonl line.
- QC_DEFENCE.md: update the entry for each finding with the verdict and the fix used.
