# Corvid SLA Credit Close - Source Register

## Purpose

This register is the entry point for the August 2026 service-credit close. It lists every export delivered to the close workspace, explains how records are counted and controlled, and fixes the reading conventions shared by all exports. Business rules live in the policy documents named in the catalog; where documents disagree the data governance charter decides which source is authoritative.

## Reading conventions

Identifiers are an alphabetic prefix and a digit run, normally joined by a hyphen (SUB-000123). Exports also write them in lower case, with an underscore, with no separator, or with surrounding or embedded blanks, no-break spaces, zero-width spaces and byte order marks; these are the same identifier. Subscription numbers have six digits, account numbers five and SDK install numbers seven. An identifier that contains any non-ASCII character or does not fit this shape is malformed, and a record carrying a malformed non-empty identifier in any identifier field is invalid as a whole. Host names are compared in lower case.

Counts may carry thousands grouping (space, no-break space, narrow no-break space, thin space or apostrophe) or a k suffix meaning thousands. A count of -1 or N/A, or a missing count, marks a placeholder record; placeholder records are ignored entirely and never supersede anything. Decimal values accept a comma as the decimal separator. A monthly fee of LIST means the price book applies.

Instants are ISO 8601 with an offset or Z (no offset means UTC), epoch seconds (10 digits) or epoch milliseconds (13 digits), or spreadsheet serial day numbers. Serials use the 1900 date system (day zero 1899-12-30) and denote UTC unless the workbook declares the 1904 date system; typed spreadsheet date-times without zone are UTC. Calendar dates are YYYY-MM-DD, DD.MM.YYYY or YYYYMMDD; 9999-12-31 or an empty value means open-ended. Fields named *_local hold local wall-clock time of the record's region.

In key/value formats (JSON, JSON Lines, XML, YAML, TOML) a field may also be spelled in camelCase. In delimited files lines starting with # are comments, the header line may be repeated later with a different column order (later rows follow the latest header), quoted fields may contain delimiters, quotes and line breaks, lines end in LF or CRLF, and a few legacy lines are Latin-1 rather than UTF-8. Spreadsheet sheets, database tables and document tables are read by their names as listed below.

Usage is measured in five-minute windows aligned to 00:00 UTC of the first day of the month; window n starts n times 300 seconds after month start. An interval [start, end) covers exactly the windows whose start instant lies inside it.

## Records and controls

A record is one data row of a delimited file (comments and repeated headers excluded), one object line of a JSON Lines file (lines carrying _meta excluded), one element of a top-level array in JSON, one element named after its table in XML, one row of a Parquet file, sheet, database table or document table, one item of a YAML or TOML list, one INI section, one log event line, one D record of a fixed-width file, one message of a mailbox and one VEVENT of a calendar. Records are taken table by table in the order listed in the catalog below, and in file order within a table.

Each file has a control field, the first field of each of its tables (for INI files the section suffix, for mailboxes the local part of Message-ID, for calendars the UID). Records are grouped in blocks of 100 in that order (block 1 holds records 1 to 100). The control sum of a block is the sum, over its records, of the integer formed by the ASCII digits of the control field as written (0 when it has none). The audit control register lists the expected record count and control sum of every block of every file; when it holds several revisions of a block the highest revision applies. Two files are controlled outside the register: edge_legacy_c.txt by the CONTROL events of ingest_reprocess.log and price_book.toml by the control entries of region_groups_2025.toml. A close may be published only when every file is present and every block matches; otherwise the close is HELD.
