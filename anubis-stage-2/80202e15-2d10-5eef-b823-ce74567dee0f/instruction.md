Corvid Cloud Platform closes its monthly SLA service-credit cycle from the exports in `/app/data`: one hundred files of collector telemetry, synthetic probes, outage and incident registers, maintenance changes, subscriptions, contracts, SLA policy, quotas, claims, treasury rates, ledgers and audit controls, in many formats. Start with `/app/data/source_register.md` (catalog of every file, reading conventions, record and control definitions, close parameters) and `/app/data/governance_charter.docx` (which source wins when sources disagree). The policies those two documents point to define how uptime and credits are computed. Sources disagree, some documents are drafts, snapshots or mirrors, and only the sections the charter designates are authoritative.

Deliver `/app/out/transform.py`, a reusable program, and the outputs it writes for the period named in the source register:

```bash
python3 /app/out/transform.py <DATA_DIR> <OUT_DIR> [--prior <PRIOR_OUT_DIR>]
```

With no arguments it reads `/app/data` and writes `/app/out`. `--prior` points at the output directory of the previous month's close; quarter-to-date state carries forward from it. The transform must also produce exactly the right outputs when it is run unchanged on the next month's exports (same file names and formats, new period in the source register, different records) with `--prior` set to your `/app/out`. It must be deterministic, read only the directories it is given, not depend on their paths or names, use only the standard library plus the parsers installed in the image, and finish within 25 minutes. Do not modify `/app/data`. There is no network.

Outputs (UTF-8, JSON documents with sorted keys and 2-space indent; JSON Lines compact, one object per line):

- `/app/out/normalized.jsonl`: one record per subscription active on at least one day of the period and not excluded, sorted by `subscription_id`, with exactly these fields: `subscription_id`, `account_id` (canonical), `product`, `region`, `region_group`, `segment`, `plan`, `sla_class`, `sla_version` (`v2`..`v5` or `custom`), `target_pct` (string, 3 decimals), `currency`, `fee_minor` (integer minor units), `active_days`, `active_windows`, `suspended_windows`, `maintenance_windows`, `eligible_windows`, `telemetry_windows`, `outage_windows`, `bad_windows`, `attributed_windows` (integers; windows are the five-minute UTC slots of the period; `telemetry_windows` counts the eligible windows that have a used telemetry record and `outage_windows` the eligible windows in which the subscription's product and region are in outage), `bad_window_digest` (first 16 hex characters of the SHA-256 of the ascending zero-based window indices of the bad windows joined by commas), `uptime_pct` (string, 3 decimals, half-even), `credit_pct`, `credit_minor`, `claim_id` (claim identifier, `AUTO`, or null), `claim_filed_utc` (`YYYY-MM-DDTHH:MM:SSZ` or null), `fx_rate` (string, 6 decimals, or null), `credit_usd_cents`, `qtd_before_usd_cents`, `cap_usd_cents` (integer or null), `status` (`MET`, `UNCLAIMED`, `CREDITED` or `CAP_EXHAUSTED`).
- `/app/out/summary.json`: `status` (`PUBLISHED`, or `HELD` when the inputs fail the documented controls), `period`, `records`, `excluded`, `status_counts`, `credited_usd_cents`, `credit_minor_by_currency`, `eligible_windows`, `bad_windows`, `attributed_windows`, and `reconciliation` (integer counts: `files` and `records` over all input files, `control_blocks` the blocks checked against controls over all files, `control_failures` the number of files whose controls fail). A held close writes only `status`, `period` and `held_reasons` (sorted list with one `CONTROL_MISMATCH:<file>`, `MISSING:<file>` or `UNREADABLE:<file>` entry per failing file).
- `/app/out/data_quality.json`: `sources` (one entry per input file sorted by `file`: `file`, `records`, `control_blocks` (blocks checked against controls), `control_ok`; the audit control register, which nothing controls, reports `control_blocks` 0 and `control_ok` true, and a missing or unreadable file reports `records` 0, `control_blocks` 0 and `control_ok` false) and `exclusions` (`subscription_id`, `reason` in `UNKNOWN_ACCOUNT`, `INTERNAL_ACCOUNT`, `BETA_PRODUCT_REGION`, `NO_SLA_ENROLLMENT`; sorted by `subscription_id`).
- `/app/out/product_summary.json`: `products` keyed by product with `records`, `eligible_windows`, `bad_windows`, `attributed_windows`, `credited_usd_cents`, `status_counts`.
- `/app/out/region_central.json`, `/app/out/region_east.json`, `/app/out/region_north.json`, `/app/out/region_south.json`, `/app/out/region_west.json`: `region_group`, `records`, `status_counts`, `credited_usd_cents`, and `regions` keyed by region code with `records`, `eligible_windows`, `bad_windows`, `credited_usd_cents`.
- `/app/out/segment_consumer.json`, `/app/out/segment_corporate.json`, `/app/out/segment_enterprise.json`, `/app/out/segment_smb.json`: `segment`, `records`, `status_counts`, `credited_usd_cents`, and `plans` keyed by plan code with `records`, `credited_usd_cents`.

`status_counts` always carries all four status keys. `credited_usd_cents` and `credit_minor_by_currency` total only `CREDITED` records. When held, every other JSON output is `{"status": "HELD"}`, `normalized.jsonl` is empty and `data_quality.json` still lists the sources with empty exclusions.
