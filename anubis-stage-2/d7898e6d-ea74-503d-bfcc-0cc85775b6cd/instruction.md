Our backup cluster's snapshot pruner was lost along with its source, and the storage pools are filling up until it is back. Everything left of it is in `/app/data`. `conventions.md` holds the rules the team wrote down, `reports.md` gives the exact shape of the three output files, and `handover.md` holds notes the last on-call engineer wrote from memory. The team does not trust `handover.md`; where it disagrees with `conventions.md` or the worked examples, it is wrong. Read all three notes before you start writing code.

Two worked examples ship with their answers. Their input files carry the prefix `example_a_` or `example_b_`, and the files they should produce carry `example_a_out_` or `example_b_out_`. The four input files with no prefix (`snapshots.jsonl`, `policy.json`, `holds.csv`, `manifest.json`) are the live intake, and nobody has its answers.

`conventions.md` says that six rules of the old pruner were never written down. Working out those six rules from the worked examples is part of the task. They cover which member of a bucket stands for it, the day a week starts on, whether a hold still counts on its `until` date, whether a partial snapshot may stand for a bucket, which copy of a republished id is used, and which clock the buckets and dates are read on.

Both worked examples use mode word zero. The live intake's `manifest.json` carries mode word 254, and the other intakes the program will later meet carry other mode words. `conventions.md` says which seven bit values are in use and that what each bit does was never written down; working out what each bit does is part of the task as well. The live intake has no answers, but its manifest carries a SHA-256 for each report and for each host's kept lines.

Write the pruner as one Python program at `/app/out/prune.py`, run as `python3 /app/out/prune.py IN_DIR OUT_DIR`. It reads the four input files with no prefix from `IN_DIR`, takes the mode word from that folder's `manifest.json`, and writes `keep.json`, `prune.jsonl` and `summary.json` into `OUT_DIR`, byte for byte in the form `reports.md` gives and replacing any copies already there. It exits with status 0 when it has written them. `prune.jsonl` must exist even when it is empty, and the `plan_digest` in `summary.json` must agree with the `keep.json` written in the same run. A run over an intake of a thousand snapshot lines should finish in well under a minute. Write it as named functions, and leave no bare `except` and no debug print in the file.

The same program will later be run on other folders with this layout, with different hosts, volumes, snapshots, policies, holds and damaged lines, so nothing about the shipped folder may be written into the program, including snapshot ids or the plan digest in code or comments. The program must use only the Python 3.12 standard library, must work with no network access, must leave `IN_DIR` unchanged, and must produce identical output when run twice on the same input. Leave everything under `/app/data` as it is.

Run your finished program over `/app/data` into an output directory of your own outside `/app/data`, and then end with a closing report that gives, for the live intake: `snapshots`, `kept`, `pruned`, `held`, `parents`, `retransmitted`, `republished` and the full `plan_digest`, each as your program wrote it, and for each of the seven reason words (`hourly`, `daily`, `weekly`, `monthly`, `hold`, `parent`, `anchor`) the number of live `keep.json` entries that carry it. For each of the six unwritten rules, state the reading you chose and name the worked example file and snapshot id that settled it, or say plainly that the examples did not settle it and you made a choice. For each of the seven mode bits, state what your program does when it is set and name the live manifest digests you compared to settle it, or say that the bit stays open. Also say whether your program reproduced both worked examples byte for byte, and whether its live reports and host digests agree with every digest in the live `manifest.json`.

A partial pruner that is written down and reported on is worth more than a perfect one that never gets finished. Put the program in place and give the closing report within your first hour, and stop any search over rules or bits well before the time limit; a session that is cut off by the limit leaves no answer at all.

You have 7200 seconds to complete this task. Do not cheat by using online solutions or hints specific to this task.
