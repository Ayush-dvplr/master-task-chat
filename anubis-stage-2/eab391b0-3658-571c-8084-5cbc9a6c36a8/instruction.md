Our monorepo's dependency resolver was lost along with its source, and the release pipeline is blocked until it is back. Everything left of it is in `/app/data`. `conventions.md` holds the rules the team wrote down, `reports.md` gives the exact shape of the three output files, and `handover.md` holds notes an engineer wrote from memory. The team does not trust `handover.md`; where it disagrees with `conventions.md` or the worked examples, it is wrong. Read all three notes before you start writing code.

Two worked examples ship with their answers. Their input files carry the prefix `example_a_` or `example_b_`, and the files they should produce carry `example_a_out_` or `example_b_out_`. The five input files with no prefix (`index.jsonl`, `workspace.json`, `pins.csv`, `lock.prev.json`, `manifest.json`) are the live intake, and nobody has its answers.

`conventions.md` says that six rules of the old resolver were never written down. Working out those six rules from the worked examples is part of the task. They cover which copy of a republished package version is kept, when a release candidate may be picked, when a yank applies, when the previous lock is honoured, the order in which one requester's requirements join the queue, and which row wins when `pins.csv` names a package twice.

Both worked examples use mode word zero. The live intake's `manifest.json` carries mode word 254, and the other intakes the program will later meet carry other mode words. `conventions.md` says which seven bit values are in use and that what each bit does was never written down; working out what each bit does is part of the task as well. The live intake has no answers, but its manifest carries a SHA-256 for each report and for each member's share of the lock.

Write the resolver as one Python program at `/app/out/lockres.py`, run as `python3 /app/out/lockres.py IN_DIR OUT_DIR`. It reads the five input files with no prefix from `IN_DIR`, takes the mode word from that folder's `manifest.json`, and writes `lock.json`, `issues.jsonl` and `summary.json` into `OUT_DIR`, byte for byte in the form `reports.md` gives and replacing any copies already there. It exits with status 0 when it has written them. `issues.jsonl` must exist even when it is empty, and the `lock_digest` in `summary.json` must agree with the `lock.json` written in the same run. A run over an intake of a thousand index lines should finish in well under a minute. Write it as named functions, and leave no bare `except` and no debug print in the file.

The same program will later be run on other folders with this layout, with different packages, versions, members and damaged lines, so nothing about the shipped folder may be written into the program, including content hashes or the lock digest in code or comments. The program must use only the Python 3.12 standard library, must work with no network access, must leave `IN_DIR` unchanged, and must produce identical output when run twice on the same input. Leave everything under `/app/data` as it is.

Run your finished program over `/app/data` into an output directory of your own outside `/app/data`, and then end with a closing report that gives, for the live intake: `picked`, `sticky`, `conflicts`, `unresolved`, `yanks_applied`, `yanks_ignored`, `republished`, `malformed`, `retransmitted`, `pins` and the full `lock_digest`, each as your program wrote it. For each of the six unwritten rules, state the reading you chose and name the worked example file and package that settled it, or say plainly that the examples did not settle it and you made a choice. For each of the seven mode bits, state what your program does when it is set, or say that the bit stays open. Also say whether your program reproduced both worked examples byte for byte, and whether its live reports and member shares agree with every digest in the live `manifest.json`.

A partial resolver that is written down and reported on is worth more than a perfect one that never gets finished. Put the program in place and give the closing report within your first hour, and stop any search over rules or bits well before the time limit; a session that is cut off by the limit leaves no answer at all.

You have 7200 seconds to complete this task. Do not cheat by using online solutions or hints specific to this task.
