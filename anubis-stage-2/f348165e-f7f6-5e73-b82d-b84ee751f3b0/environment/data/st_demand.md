# Demand from the request logs

Each request log holds the requests of one traffic class for the settlement window of that class. A log is an RQB1 container; lg_rqb.md gives how its records become requests. A class may have more than one request log: its requests are those of all its logs, and a request found in more than one of them (the same req_id) is one request. Every request has the fields req_id (text, unique within the log), api_key (text), model (text), prompt_tok and completion_tok (whole token counts), done_at (the completion instant, written as YYYY-MM-DDTHH:MM:SSZ in UTC), status and traffic_class, and every request of one log names the same class.

Window membership: the control file gives each class a window as a start instant and an end instant. A request belongs to the window of its class when its completion instant is later than the window start and not later than the window end. A request completed exactly at the window start belongs to the window before, and one completed exactly at the window end belongs to this window. Requests outside the window are counted as out of window in the data quality report and add nothing to demand.

Status: a request with status ok counts its prompt and completion tokens. A request with status cut counts its prompt tokens only. A request in the window with status rejected counts nothing and is counted as rejected in the data quality report, whatever its key. The status of a request is the one its selector gives (lg_rqb.md).

Token units: each counted token is weighed by the weight of its model from the model weight table (the document mm_04.docx): prompt tokens by the prompt weight and completion tokens by the completion weight. The token units of a request are the sum of both weighed counts.

Tenants: a request reaches a tenant through its api_key. The alias table of the register maps keys to tenants, each row in force from its effective instant, which it includes. A request takes the alias row of its key with the latest effective instant not later than its completion instant. A request in the window with any other status whose key has no alias row in force at its completion instant is an orphan: it adds nothing to demand and is counted as an orphan in the data quality report. A request that reaches a retired tenant, or a tenant in no pool of the class, is also an orphan.

Demand: the token units of a tenant are the sum over its counted requests in the window. Its demand is converted to RU as pr_num.md states, with the units per RU of its pool.

Meter readings: each reading of the meter sheet (the document ku_11.pdf) was taken at its reading instant over the api keys it lists. Its value is a sum over the distinct members those keys reach at the reading instant, each key through the alias row in force at that instant: for each such member, its token units counted from its requests completed at or before the reading instant, divided by the units per RU of its pool and rounded up to a whole RU. A key that reaches no member at the reading instant adds nothing. The units per RU of the pools are the admissible values (gl_00.md) that meet every reading of the sheet together; a pool with a member whose token units are not zero needs one, and a pool without such a member needs none. A reading may name members of several pools, so a pool is settled by the readings as a whole, not by any one of them.
