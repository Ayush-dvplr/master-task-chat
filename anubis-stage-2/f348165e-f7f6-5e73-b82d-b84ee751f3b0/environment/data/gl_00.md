# Glossary of export codes

The files of an extract are named by operational export codes, not by meaning. This glossary gives the role of every code that can occur.

| code | role |
|---|---|
| am_07 | amendment layer of register corrections (tab separated) |
| ct_svc | service contract |
| ctl_r7 | control file of the settlement period |
| ed_cases | boundary cases of the stages |
| ev_ followed by digits | request logs (RQB1 containers); each names one traffic class, and a class in scope has one or more |
| fm_reports | report forms |
| lg_rqb | grammar of the request log container |
| gl_00 | this glossary |
| ku_11 | meter sheet: readings of reserved throughput (PDF) |
| mm_04 | model weight table (Word document) |
| od_stage | stage dependencies |
| ov_07 | override layer of register corrections (JSON lines) |
| pp_31 | pool profiles: starting step, patience and budget per profile code |
| pr_num | precision and rounding |
| px_prev | settled reservations of an earlier run |
| rc_23 | rate card (workbook) |
| st_bill | billing of settled reservations |
| st_demand | demand from the request logs |
| st_settle | reservation settlement |
| tn_mirror | tenant table export |
| tn_reg | register database |
| xw_05 | group crosswalk from pool group to profile code |

Model weight table: the document body holds one table whose header row reads model, prompt_weight, completion_weight; every later row gives a model name and its two weights as whole numbers.

Meter sheet: the PDF holds one page whose text lines read the word reading, a reading id (the letter M and digits), the reading instant (written as in st_demand.md), the reading in RU as a whole number and one or more api keys, separated by single spaces; other lines on the page are headings.

Rate card: the workbook has a sheet named rates whose first row is the header traffic_class, eff_from, ru_rate_micro, over_rate_micro, round_fee_micro; eff_from is a date written as YYYY-MM-DD and the three rates are whole numbers.

Units: RU is one reserved throughput unit for the settlement window. A micro-credit is one millionth of a platform credit.

## Terms

| term | meaning |
|---|---|
| api_key | the key a request was sent with; it reaches a tenant through the alias table. |
| budget | the profile column giving the most rounds a pool may close. |
| contracted reservation | the contracted_ru of a tenant row once corrections are applied. |
| cutoff_seq | the correction cutoff of the control file. |
| cycle | the states a pool passes through from the first sighting of the state it repeats up to the round that closes on that state again; the starting holdings count as a state the pool has held. |
| done_at | the completion instant of a request. |
| eff_from | the effective instant (alias table) or effective date (rate card) from which a row is in force. |
| furthest from its target | said of the member with the largest absolute difference between its target and the sum of its holding and its raw movement. |
| grp | the group of a pool in the pool table; the crosswalk maps it to a profile code. |
| halve | to replace the step by half of it as st_settle.md states; a step halved in a round governs the movements of that same round. A step of one quarter is halved like any other step: it stays one quarter, and the halving still returns the patience count to zero. |
| improve | a round improves when its residual total is strictly below the residual total of the round before it. |
| label | the name of the settlement period in the control file. |
| member | a tenant of a pool after corrections, retired tenants left out. |
| micro-credit | one millionth of a platform credit. |
| nearest whole unit | the whole number closest to a value; an exact half goes to the whole number nearer zero. |
| patience | the profile column giving the patience count at which the step is halved. |
| patience count | the number of rounds of a pool that did not improve since the step was last halved, or since round zero when it never was; it returns to zero only when the step is halved. |
| pool total | the sum of the starting holdings of the members of a pool. |
| prof_code | the profile code of a crosswalk row or profile row. |
| rate row | one row of the rate card sheet rates. |
| round count | of a pool that settles or stalls, the number of the round in which it settled or stalled; of a pool that stops on its budget, the budget; of a pool that cycles, -1. |
| RU | one reserved throughput unit for the settlement window. |
| standing | a member's holding at the opening of the current round; its standing holdings are the holdings the pool opened that round with. |
| start_step | the profile column giving the starting step in quarters. |
| state | the list of the holdings of a pool's members in member name order. |
| step | the movement factor of a pool in quarters. |
| token units | token counts weighed by model weights, as st_demand.md states. |
| traffic class | one of visible, peak, steady, burst and latency. |
| units per RU | the token units one RU covers in a pool. Each pool has its own, a multiple of 100 from 1200 to 5000; no document states it, and st_demand.md gives how the meter sheet settles it. |
| window | the start and end instants of a traffic class in the control file. |
| yield | what a round yields is its movements after the correction that brings their sum to zero. |
