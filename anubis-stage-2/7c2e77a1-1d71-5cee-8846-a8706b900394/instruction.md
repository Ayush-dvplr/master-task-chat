# Pulldown Cadence Conform

You are the conform engineer at a post house that assembles delivery timelines from vendor source clips. Every correction stream, reference table, configuration layer and observation log the house holds sits in `/app/data`. The document `/app/data/conform_contract.md` is the single source of truth for how a timeline resolves, and `/app/data/index.md` names every file with the tier of authority it carries. The documents beside them settle timecode counting, provenance, record layout and scenario membership. Nothing tells you which parts of the material are wrong; finding that out is the task.

The house runs five delivery scenarios named visible, peak, steady, burst and latency. Build a conform engine at `/app/out/optimize.py` that resolves one scenario against the contract. It must expose `run_scenario(data_dir, scenario)` returning the scenario record as a dictionary, and must also run as `python3 /app/out/optimize.py --data-dir D --scenario S --out F`, writing that record to the path given. Your engine will be run again on extracts nobody has seen, holding the same file names with different events, configuration values and reference windows, so every rule it applies has to come from what it reads at run time.

Write the resolved record of each scenario to `/app/out/scenario_visible.json`, `/app/out/scenario_peak.json`, `/app/out/scenario_steady.json`, `/app/out/scenario_burst.json` and `/app/out/scenario_latency.json`. Each carries `scenario`, `cutoff_utc` exactly as the configuration writes it, the resolved `delivery_family`, a `timelines` list ordered by rising timeline identifier, and a `totals` map. Each timeline carries `timeline_id`, `record_frames`, `exit_phase`, `applied_events`, `audited_events`, `rejected_events` and an `events` list in resolution order. Each event carries `event_uid`, `canonical_code`, `generation`, `outcome` drawn from applied, audited and rejected, `reason_code` from the closed set the house publishes, `source_frames`, `record_in_frames`, `record_out_frames`, `phase_in`, `phase_out`. The totals map carries `timelines`, `events`, `applied_events`, `audited_events`, `rejected_events`, `record_frames` and `exit_phase_sum`.

Write `/app/out/perf_report.json` with `module` set to the engine path, `method` set to `relative repeated median`, a `scenarios` map holding `input_events`, `admitted_events`, `applied_events`, `record_frames`, `median_ns`, `reference_median_ns` and `speedup` per scenario, a `totals` map summing the first four, and `ok` set to true. The speedup is the reference median over your own median rounded to three decimals, and your engine has to resolve a scenario faster than the legacy module.

Write `/app/out/bottleneck_analysis.json` with `reference_module` naming `/app/data/reference_conform.py`, a `stages` list taken from the stage list that module publishes, a `stage_visits` map per scenario holding the visit count the house signed off per stage, a `dominant_stage` map naming the stage with the most visits, a `hot_timelines` map holding the five timelines of each scenario with the most applied events by falling count then rising identifier, and a `phase_carry_timelines` map counting timelines whose exit phase is other than zero.

Write `/app/out/recommendations.json` with a `scenario_actions` map holding, per scenario, the three leading reason codes by falling count then rising code, each entry carrying `rank` from one, `reason_code`, `count` and the `remedy` the house publishes; a `global_top_reason`; and a `global_counts` map of each code that occurred to its count across the five. Write `/app/out/data_quality.json` with a `scenarios` map holding, per scenario, a `rejected` map of reject code to count, an `audited` map of audit code to count and a `withdrawn` count, with a `totals` map holding `rejected`, `audited` and `withdrawn` summed across the five.

Write every record with sorted keys, no spaces between tokens, and one trailing newline. Frames, phases and tallies are JSON numbers. A record counts only when every figure is exact; one frame out of place on one event fails the artifact holding it, and the same holds for every map and count above. Leave `/app/data` exactly as you found it, write nothing into `/app/out` beyond the ten paths named here, and write no partial record if resolution stops.

Close with a short message to the delivery supervisor. Give the number of applied events in the visible scenario whose record out frame would land elsewhere if the cadence phase restarted at zero for every event, carrying that restarted count forward through the timeline, and give the same figure summed across the five scenarios. Give how many events took their measurements from the tape index and how many of those came from the later of the two indexes, counting only events that reached the point of measuring the source. Give how many delete records a higher revision superseded and how many correction records changed nothing because an identical record already stood, counted over the records each scenario admitted by recorded time before the revision on the event row is brought to bear. Give how many revision contests settled on source standing and how many settled on recording time, counted over every contest the correction streams raised, including contests naming an event the scenario does not carry. Give how many events the ingest logs carried past the cutoff that the event row on its own would have admitted, and how many admitted events carry a resolved recorded time equal to the cutoff instant. Give how many timelines sit inside the longest closed nesting ring and the lowest identifier within it. Give how many overrides were turned away for want of approval scope and which approver accounted for the most, counted over the overrides that take part by recorded time, weighing approval scope on its own so that an override turned away on timing as well still counts here, together with how many of those arose in the visible scenario and how many the leading approver accounts for. Give how many events took their recorded time from an ingest log rather than their own row and which host contributed the most, counted over every event the shards of the scenario carry whether or not the cutoff admitted it. Give how many speed conversions landed exactly on a half frame among applied events and which scenario held the most. Give the ordering you settled revision contests under and how many recorded contests you fitted it against. Counts without a named scenario cover all five. Say plainly what you settled each withheld rule on and what in the material told you so. None of these figures belongs in any artifact.

Work offline from the shipped material, using the Python standard library. Do not search online for solutions, hints or reference implementations. You have 10800 seconds to complete this task.
