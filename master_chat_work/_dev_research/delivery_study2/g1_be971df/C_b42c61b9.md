## 3. Core difficulty
A correct program must decode seven independent sub-problems (memo PDF text reassembly, workbook date1904 + FX sheet named by profile, time-gated identity walk with cycles, refund replay, multi-currency valuation with cross rates and half-even ties, the stats stack, and capacity-ranked decisions). It must also stay exact on structures the shipped corpus never contains: four arms (3 dof), SHORTENED windows, capacity ties, a zero-capacity team, and other registry/FX releases (TRUTH.md:58-61). The agent solved the shipped instance completely (decisions match TRUTH.md:48-51; every final-message fact passed) in 8 minutes of reading and one 1,706-line program. The loss comes from an unseen branch plus a gate that multiplies it: one core report wrong on one of 8 corpora → 61 points.
- Class: **scale of surface + rules whose branches fire only on hidden corpora (stated, but untested by shipped data) + stated all-corpora gate**. It is not a hidden rule, because every branch is written in the handbook, most with a worked example.
- Why a blind Opus does not transliterate this in 3 minutes: the spec is explicit, but it is long and spread over 3 authorities in 3 binary-ish formats. About 40 rules interact. The shipped data exercises only a subset, and Opus self-checks only on shipped data plus one "changed copy" that changed settings, not structure (trajectory step 64-65). This is the same mechanism as our "transliterated contracts", but with breadth × unexercised branches × gate, which beats Opus where depth alone did not. This is INFERRED because the failing branch is unpinned.

- Gate: `CORE` :2442, `_core_exact` :2447, `_full_core` :2458 (seven core reports exact in /app/out and in reruns on all 8 corpora). Every w3/w5 check calls it.
- Comparison: the reports are parsed and compared exactly after parsing their format, with no tolerance (`_canon/_eq/_same` :957-996).
- Runs: under `setpriv` nobody (:58) with `_run` :2537 and `_renamed` :2492, so the program is also run under different file names.
- Wrong-reading negatives (`_flipped/_matches_flip` :2593-2604) fire only when the delivered report equals the verifier's derivation under the named wrong reading AND differs from truth. These are narrow, so TS-16-safe.
- Shares: hidden-dependent 61/67 (91%); ungated shape 6/67. stacking_check printed isolated/observable rows but cannot see the `_full_core` coupling, so its hints are misleading for this file.

## 8. Leak avoidance
- The instruction names the authority order and says the published run is wrong, but never names a defect: "wrong in ways that reach almost every test and decision" (instruction.md:1). → W1, LV1.
- The rule docs are fully explicit and carry worked examples, but every worked example is on an invented toy case (handbook H1.5 E→F link, H10.3 ratios, H12 chi2 = 2), never on shipped records. → LV3, W6-compatible.
- The separating cases (4 arms, SHORTENED, capacity tie) are absent from shipped data and appear only in held-out corpora. → W5, S2 (data-rule no-op on shipped).
- Decoys are refuted collectively by one authority sentence at the top of the handbook (handbook:3-11), not file by file next to each decoy. → close to LV6. This is safe here because Opus handles decoys well (it rejected all 10).
- Binary authorities (PDF with scrambled TJ runs, xlsx with a hidden draft sheet) put the rules behind a decoding step, but the step is solvable. Opus solved it in steps 9-15.
- LEAK_LIBRARY: the "shipped boundary rows" common cause is avoided (no shipped row hits the hidden-only branches). The V0 numbered-steps row would normally predict transliteration; here transliteration happened but was not enough, because the gate punishes untested branches.

## 11. Take-aways
- **SAFE, KNOWN (S2/W5):** put the separating structures only in hidden corpora, and state their rules in the spec with toy-case worked examples. Opus implements them but cannot self-verify them on shipped data.
- **SAFE, NEW (judge):** criteria of the form "agent executes the spec's printed worked example for branch X and compares with the printed value", where X never fires on shipped data. They cost a strong agent about 3 points each, are fair (the example is printed) and do not overlap any test (JD-8 clean).
- **RISKY, KNOWN (R9 stated core gate):** an all-corpora core gate turns one branch slip into 91% of the test points. QC passes it as a CL-4 WARN when the instruction states it out loud. It works for hardness, but the reward cliff makes the score high-variance.
- **NEW build technique:** the embedded generator re-emits binary authorities (xlsx writer, PDF writer with text-run scrambling) per hidden corpus, so format-decoding levers stay live on hidden data instead of being solved once.
- **NEW build technique:** metamorphic hidden corpora (shipped feeds + changed governance table; shipped feeds + profile switched to the other rule-sheet/FX release) test "reads the authority" separately from "handles new structure".
- **SAFE, KNOWN (TD8/G4):** flip negatives that fire only on an exact match with a named wrong reading AND a difference from truth.
- **AVOID:** a thread-unsafe test cache under rewardkit's 8 parallel checks. The oracle scored 9/67 before the fix (QC :35-46). Always build memoised grader state under per-key locks.
- **AVOID** relying on breadth alone: the shipped instance was fully solved in 24 min. The points came from the gate × hidden branches, not from any single hard rule.
