## 11. Take-aways
- ADOPT (RISKY, KNOWN K1/R2 with NEW mechanics): a finishing pass that plants one behaviour in every hidden corpus, with uniqueness asserted per corpus, and a shipped instance where that behaviour is a no-op. Devastating (94.8% lost) but it is a hidden rule; our rules forbid it unless a sentence or determinate fact exists. A SAFE variant for us: state the rule neutrally in the governing file ("settings are fitted per period between ...") and keep the shipped data degenerate.
- ADOPT (SAFE, NEW): put the hidden-tier behaviour inside a what-if question (a counterfactual the agent must compute once). It makes the rule visibly "possible" (QC reachability argument) while Opus treats it as a one-off and does not generalise it into the program.
- ADOPT (SAFE, NEW): a shipped column that is right on shipped data and wrong on hidden data (shortcut decoy that only hidden corpora punish). Needs a governing sentence naming the real source (here `record_dictionary.md` omits the column).
- ADOPT (SAFE, NEW judge shape): program-property criteria "accepts a fitted constant only when exactly one candidate reproduces the evidence" and "explicit empty-fit path, no preset fallback"; Opus systematically returns the first fit and seeds with presets. Oracle must satisfy them (JD-7).
- ADOPT (SAFE, KNOWN J2): "runs the program on a changed copy; a byte-identical copy does not count".
- AVOID: decoy document that asserts the opposite of the hidden rule when no governing sentence exists (it makes the hidden rule look like a contradiction rather than a lever).
- AVOID: uniform gate across all hidden corpora: the 22 differently themed corpora collapse into one test of one behaviour; per-corpus edge rules are never graded independently (CL-4 tracking weak).
- Build technique: grade-time corpus factory = mutations of an embedded shipped copy + fresh draws with new calendars/DST, all routed through a common finishing pass; audit-hook wrapper for path discipline.
