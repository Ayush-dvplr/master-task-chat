## 3. Core difficulty
- A correct module must recover, per extract, the kind weights the rate card leaves FREE (5-11 free weights in 2..40 on the hidden extracts, TRUTH.md:12) by a constraint search pruned by replaying the withdrawal journal as soon as a weight is fixed, jointly with a per-extract cancellation table, then confirm exactly one fit against the standing journal. Plain enumeration of the weight box is 39^5..39^11 and cannot finish.
- The shipped extract is deliberately degenerate (TRUTH.md:186 "the shipped extract is degenerate"): its card is full rank, so the weights fall out of linear algebra and the hard search never runs on anything the agent can see.
- Class: computational core (constraint search over withheld constants) + scale/runtime, made invisible by a degenerate shipped instance. Not a misread sentence: every rule is stated (rate_card.md:8-9 "a whole number from 2 to 40, whether or not the kind appears on the rate card"; performance_contract.md 60 s for "up to 15,000 workload rows, 12 kinds").
- Why a blind Opus does not transliterate it in 3 minutes: there is nothing to transliterate. The documents state a search SPACE (families of rules, a weight box), not a method; the fast method (prune by journal replay) is never stated, and the only shipped instance does not need it. Contrast our parked builds, where stated limits handed over the exact method.

## 11. Take-aways
- ADOPT (SAFE, NEW): degenerate shipped instance. Ship an instance where the hard core collapses to a closed form (full-rank system, unique fit), state the general space and size bound in plain sentences, and put all weight on hidden instances where the core must actually search. Opus's self-tests mirror the shipped instance and miss the branch.
- ADOPT (SAFE, NEW): judge what-if questions that weaken the shipped evidence so the hidden core becomes visible, paired with a negative that fires when the answer came from a side script carrying shipped constants (process negative quoting a "changed copy is an instance in its own right" sentence).
- ADOPT (SAFE, NEW): honesty-of-coverage negative: "claims X generalises while the trajectory has no run of X on a case where property P holds" (R20 shape), and "states a size/count for its own check that differs from what it printed" (R19 shape).
- ADOPT (SAFE, KNOWN TD1/G8 variant): hidden extracts with their own FILE NAMES routed through a rules file, so path hard-coding fails; act-only negative that compares output to the shipped-configuration result on a re-rated copy.
- ADOPT (RISKY, KNOWN K3): one shared configuration stage gating 92% of points; passes QC only with an explicit exact-bar instruction sentence; violates our G10 lever-independence.
- Build technique: rule families written as closed candidate spaces (ranking: one measure of four, direction, tie by position; standing: count O/L, total U/C/U+W, at-least/strict, least/greatest fixpoint) plus an exhaustive uniqueness proof in TRUTH; this is how IN-16 is satisfied without stating the rule.
- AVOID: describing a trap in TRUTH that no graded input springs (AL-27 FAIL before fix).
