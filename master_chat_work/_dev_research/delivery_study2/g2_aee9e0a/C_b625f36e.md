## 11. Take-aways
- **SAFE, KNOWN (DL TD1):** an embedded seeded generator rebuilds both tiers in the verifier, and the verifier never reads /app/data (T:2831). The hidden tier is regenerated, not shipped.
- **SAFE, NEW (wording):** an "N figures, none of which appears in any file you leave behind" clause. It forces separate counterfactual computation, and figure criteria escape JD-8 overlap.
- **RISKY, NEW:** counterfactual-count criteria ("how many X would differ under habitual reading Y"). Strong agents lose 1-off counts. Fair only if each variant is pinned by one sentence; ambiguous variant wording (R2) turns this into an artefact.
- **AVOID, NEW variant of N3:** an undefined loop/termination branch in a chain-walk rule. The reference picks one stop point, and both readings are internally consistent, so no self-test can find it. That is a hidden rule even though the "per-hop" rule is fully stated.
- **AVOID, KNOWN (K2):** wrong-reading negatives on populations that an upstream hidden rule also touches. Here the probe fired without the act ever happening.
- **RISKY, KNOWN (K3):** a claim of "one check per rule" while sort keys and downstream columns depend on one upstream column. The amplification is real (72/97 from one branch) but reads as a cascade.
- **Build technique:** 6 serialisations of the same record family plus 3 config layers with a last-wins vs smallest-wins namespace split. Cheap to generate, and Opus handled all of it, so it is noise only (LR §0).
