## 3. Test architecture
- **How expected values are produced: a reference implementation runs at test time over embedded copies of the shipped inputs.** Docstring tests/test_output.py:1-7: "Independent re-derivation: every expectation is recomputed here from the shipped evidence embedded below, never read from the agent's answer files." `_BLOBS` (:63-121) holds zlib+base64 copies of every `/app/data` file. The reference functions are `defs` :151, `as_int` :161, `keep` :171, the per-format parsers `triples` :192-313, `reduce_corpus` :316, `wanted_aggregates` :333, `op_ok` :383-410, `_stateful_replay_for(env,start)` :413-453, `wanted_rejected` :456-465, `rekey_shift` :475-482, `_zone_start` :495-503 and `wanted_profile` :506.
- **Hidden vs shipped inputs:** nearly everything is graded on the shipped corpus. The only unseen input is in `cli_reproduces_derived_outputs` (:1074), which runs the agent's `aggregate` subcommand on a private copy of one corpus (EVAL_SEED :61). stacking_check reports "G3 hidden 0% FAIL"; that is roughly right (one w5 check runs on a private copy).
- **One input depends on the agent's own artifact:** Z = sha256 of the agent's own `tool.zip` (:475-482). The expected aggregate is therefore a function of the agent's artifact, but its correctness is checked by the reference (`zip_shift` :1178). This makes the answer key impossible to hard-code.
- **Isolated vs whole-document:** each artifact is compared whole (`_canon` :565 json sort_keys indent2; config, profiles and rejected list compared to `wanted_*`). The **anchor design** in `_anchor` :530-546 compares the agent's `aggregates.json` with the reference reduction at the true shift; ≥45 of the 50 corpora must match. Once anchored, the 7 mirrors, `corpus_index`, `posture` and `summary` are compared against the **agent's own** aggregates. One wrong corpus therefore costs only `aggregates_match`, while a wrong shift costs the whole family (TRUTH.md:176-185 states this intent).
- **Partial credit:** none inside a check (boolean). The design partition is: a family is gated on the anchor, then the mirrors grade only format.
- **Unstated gate `_real_work` (:553-562):** at least one of {config == wanted, rejected == wanted, aggregates anchored} must hold. Five w3 checks call it at :1133, :1144, :1157, :1166 and :1234: `json_artifacts_canonical`, `commands_through_cli_count_matches`, `zip_shift_present_and_coherent`, `profile_trailer_embeds_config_sha_prefix` and `config_sha_in_posture_matches_file`. Its purpose is anti-cheat: a format check should not pay a hand-written stub. The side effect is that a genuine but wrong pipeline loses its format points too.
- **Program runs:** the agent's `cli.py` is extracted from its own `tool.zip` and run as `nobody` via setpriv (`run_tool` :664-687; it chmods /app paths first; the comment cites TS-30), timeout 120 s. `_replay_transcript_rebuilds_config` :594-628 replays the init/set argv that the agent recorded in report.json and requires a byte-identical config.json.
- **Negatives (none fired):** hardcoded -5, nested_or_dynamic -5, fake_transcript -3, network_or_secret -3, no_homoglyph_counts_leaked -5, no_svc_in_zone_totals -5 (:1079-1094, :1221, :1226). The last two are lever-shaped: they fire when look-alike zone tokens are counted.
- **Mutation tests:** none in the G6 sense. The Z term means the shift varies with the agent's own zip bytes, which acts as a natural per-run mutation of the bound.
- **stacking_check corrections:** it labels 74.2% "isolated" and 25.8% "shipped_only" with 0 whole-doc. From the code, every check is whole-artifact equality on the shipped corpus, and 13+3+3 = 19 pts are anchor-gated mirrors (dependent, not isolated). Its AL-28 "UNMATCHED group" (no_homoglyph -5 + no_svc -5 + judge R7 -5) is a heuristic grouping; the three are different acts (two count different bad tokens; R7 is external retrieval).

- **TS-26 (no double payment):** the mirrors read separate files, but all are paid off one fact (the shift). QC accepts positive cascades (QC_RULINGS.md:125 "TS-26 and AL-28 failures ... were all on negatives, never on positive cascades"). This task is a stronger case: one fact pays 77 points.
- **IN-15:** each formula, token rule and format is stated at least once (instruction:7-31, contract:7-72, :236-261). The one gap is the base-only scope, which is not a sentence.

## 6. Leak avoidance
- Wording:
  - (a) "its `env` is listed in `journal_envs`" (contract:19). This is a true validity rule that reads as a scope rule (W3: clause in a long enumeration).
  - (b) "replay the valid journal operations whose `env` is that zone ... against that zone's own state" (contract:37-39). The restriction is written only for zones, never for the spine (W2: the rule sits in the section that governs other data).
  - (c) "The spine state after each op is the state used to validate the next op" (contract:238-239). "The spine state" invites a single shared state (W3: definition with a branch, no warning).
  - (d) "any error anywhere in the pipeline ... moves the effective upper bound" (instruction:31). The amplification is announced, but not which error (W1 respected).
- Shipped data separates the readings only in the last ~34 seq numbers (9001-9034): zone ops are interleaved with base ops at the very end of a 9034-line journal (step 16). Nothing shipped shows the expected spine, and there is no control value (W5/W6/W7 respected: no honest control to check against).
- No visible tests and no worked examples. The decoy envs (`'сore'`, `'Core'`, `'core '`, zero-width) draw attention to byte-exact env matching, which the agent handled correctly (rejections 9029-9034 at step 25), and away from scope.
- Naming: "spine" for the base config, plus a `--env base` CLI flag. The reader has to infer that "base" is an env like the zones.
- Compared with LEAK_LIBRARY CR-5 ("two duplicate notions split across 2 files but each fully explicit"): we stated both halves explicitly and the agent copied them. Here the base half is never written, only the zone half. Compared with LEAK_LIBRARY common cause 1 ("every rule was one explicit sentence that named its own exception"): this rule has no sentence at all for the spine branch.

## 9. Take-aways
- ADOPT (SAFE): compute expected values with an embedded reference over embedded inputs at test time; nothing on disk can be copied, and QC accepts it as "independent re-derivation".
- ADOPT (SAFE): anchor dependent views on the agent's own primary artifact once that artifact matches; one row error costs one check, while an upstream error costs the family. QC passes it when the instruction announces the cascade.
- ADOPT (RISKY): fold a value from the agent's own deliverable (a hash of its archive) into every expected number. It defeats hard-coding, but every upstream slip moves all values, and QC has to accept the CL-4 amplification through an instruction sentence.
- ADOPT (RISKY): write a scope restriction only for the narrower branch, and leave the main branch to an enumeration that lists every env as valid. It worked, but an IN-16 reviewer could call it two readings.
- ADOPT (SAFE): put the separating events only at the tail of a long stream, interleaved, with byte-level decoys on the same lines to draw attention.
- AVOID: an unstated `_real_work`-style gate on format checks. It cost 15.5 points that were not about the property tested, and it is a TS-19 "stricter than contract" risk.
