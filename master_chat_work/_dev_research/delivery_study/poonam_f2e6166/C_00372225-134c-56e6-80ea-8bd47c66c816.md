## 4. Lever table (FAILED checks)
**One rule causes every failure.**
- Rule: the convergence fair share is fixed once from the admitted state before round 0 (reference test_output.py:251-264, then the loop L272-300; solution/solve.py:287). It is not recomputed each round.
- Every location of the rule, which is the only place "fair" appears in the data docs or instruction.md (grep):
  - stage_note_convergence.md:3 "settle the admitted analyte masses by damped proportional rebalance toward the fair share"
  - :5 "The fair share splits a target mass across the analytes in proportion to what they already hold. The target is the batch mass when that mass sits at or below the batch cap, and the batch cap otherwise."
  - :7 "Settle in rounds, counting the rounds from zero ... The residual of a round is the sum over analytes of the absolute difference between the mass an analyte holds and its fair share."
- Sentence form: **implied by a definition**, plus **scope by omission**. No sentence says when the fair share is taken. The intended reading has to be inferred from the definition sitting before "Settle in rounds", the singular "the fair share" and "the admitted analyte masses". Inside the loop, "what they already hold" reads naturally as the current masses.
- Agent's reading: derive_report.py:275 `fair = fair_share(masses, order, cap)` is inside the round loop. Step 20's debug trace prints fair recomputed per round. Masses go negative (e.g. `r1 masses (49193,-6,-4094,-4396)`) and the trace ends "CYCLE at round 11". The agent kept the reading and only moved the zero-flow stop (step 21).
- Correct reading: fair share is computed once from the admitted masses, with target = min(mass, cap). When batch mass > cap the residual can never reach 0 (mass is conserved), so the loop ends by stagnation, cycle or cap.
- Why the self-test missed it: the agent had no oracle. Its self-tests (steps 25-26) mutated lots, slots and analytes and checked that the program ran and that eligibility changed. Nothing checked convergence values. The negative-mass symptom was visible at step 20 and went unquestioned. All three shipped batches are over cap, so the shipped data does separate the readings, but no expected figure is shipped.
- Fully stated somewhere visible? **NO -> HIDDEN RULE** (binding time never stated). TRUTH.md:6-20 lists 8 designed traps and this is not one of them. TRUTH's measured variants (L110-123) include none for convergence. INFERRED: an unintended ambiguity that QC did not flag (IN-16).
- Nearest of ours: **L6** (scope carried by a definition) or **L3/H6** (state consumed or reused across rounds). Proposed **NEW: "binding time of a defined quantity"**, meaning a quantity defined once and then used inside a loop, where the text never says snapshot vs recompute.

## 9. Take-aways
- SAFE: a generator in tests/ that regenerates the spec text with every corpus, so the hidden runs are provably under the same rules.
- SAFE: tiny per-rule probes carrying constants that differ from shipped, so hardcoding fails and each check is about the rule.
- SAFE: whole-document checks gated by a core-exact helper while mid-derivation checks stay ungated. This was accepted by QC as CL-4 cover when the instruction states the cascade.
- RISKY: the lever that actually worked was an unstated binding time (a defined quantity used inside a loop). It would fail IN-16 if a QC reviewer noticed it. Deliberate use needs a sentence that technically fixes the binding in a far-away governing file (W2/W3), not silence.
- RISKY: a probe check that compares only a downstream figure (objective) lets one stage error cost a different stage's check. It makes the task harder but breaks probe isolation (G2).
- AVOID: a "footguns" file listing the traps. Every trap it named was passed.
- AVOID: `and`-bundled multi-observable checks (TS-13). They passed QC here, but QC_RULINGS marks them MINOR.
