Board 5087cd2. Kit HEAD 71a653b2. Paths are relative to `Terminal_2.0_Harbor_Harness/Input_Bundle_QC/`; `01` = `01_Instruction_QC.md` and so on, `FC` = `Final_checklist.md`.
Verdicts: **CONFIRMED** = following one check as written can fail the other, or the two give different severities for the same fact. **SQUEEZE** = no contradiction, but together they leave a narrow legal zone. **REJECTED** = the suspected fight is not there once both texts are read. Script results come from the probes in `SCRIPT_RULES.md` (scratch copies only).

## A. Real contradictions (CONFIRMED)

### K1. TS-12 vs JD-16(4): a format rule left to the judge is fail in gate 03, warn in gate 04
- 03:42 TS-12: "a format, output-shape or declared-artifact scope rule left entirely to the judged channel is a real finding." 03:135 severity: "fail: TS-1, TS-2, TS-4..TS-12 violations".
- 04:97 JD-16(4): "When a constraint criterion enforces a rule a test could have checked and no test checks it, say so and name the assertion that would have worked. Warn rather than fail: the criterion is valid and what suffers is signal quality". 04:146: "warn: ... JD-16 a constraint criterion carrying a rule a deterministic test could have checked".
- Mechanism: one fact (a shape rule graded only by an `instruction following` criterion) gets two severities. FC:442 "The bundle verdict is the worst finding present", so gate 03 wins and the bundle is FAIL.
- Narrow zone: grade the format/shape/declared-scope rule with a test and drop the criterion (adding the test while keeping the criterion is JD-8 overlap, 04:77 "Same observable = overlap = fail").

### K2. IN-15 (literal) vs JD-15 / IN-8 / AL-1: conduct criteria and "graded HOW"
- 01:45 IN-15: "If a test or a judged criterion grades HOW the agent worked, the rule must appear in the contract".
- 04:92 JD-15 Step 1: "would every competent route to a correct end state satisfy this criterion? If yes it is legitimate and needs no instruction sentence". 01:38 IN-8: "a conduct criterion needs no sentence anywhere, because requiring one would force the working method into the prompt, which IN-14 forbids". 05:21 AL-1 says the same.
- Mechanism: a conduct criterion literally grades HOW. IN-15's first sentence fails it; the IN-8 carve-out exempts it. IN-15's procedure lists only criteria with `type = "instruction following"` (01:45 "list every criterion whose ... carries `type = "instruction following"`"), so a reviewer who follows the procedure passes; a reviewer who quotes the first sentence fails.
- Narrow zone: label conduct criteria `agent behavior`. A conduct criterion that fails JD-15 Step 1 and Step 2 cannot be rescued by adding an instruction sentence, because the sentence turns it into a recipe (IN-14).

## B. Squeezes (both checks hold; the legal zone is narrow)

### Q1. CL-4 vs whole-document cascades (TS-26 / JD-14 do not block them, CL-4 can)
- FC:491 CL-4: fails "a pile of separately weighted tests that all key off that same single comparison"; "Report what an answer with exactly one fact wrong would score." Exemption: "An instruction that states out loud that only an exact match counts has set that bar deliberately."
- 03:53 TS-26 only bans "the same observable with the same decisive logic"; "What is NOT a duplicate: two tests reading genuinely different aspects of the same object". 04:91 JD-14 the same.
- Mechanism: a cascade where one upstream misreading fails N downstream documents passes TS-26/JD-14 (different observables) but is exactly CL-4's near-miss-scores-as-total-miss shape when one wrong fact zeroes most of the positive weight.
- Narrow zone: (a) the instruction says out loud that whole documents are graded exactly (CL-4 exemption; LEVER_RULES G5), and (b) isolated rule checks on correct upstream inputs keep the curve able to "tell a near miss from a total miss". Our LEVER_RULES L35 "None forbids one upstream mistake failing several different observables" is true for TS-26/AL-28 but not for CL-4.

### Q2. AL-27 trigger depth vs TS-23 / JD-12 caps and TS-13
- 05:27 AL-27: "For every ordering, precedence, or tie-break rule ... for each adjacent pair in the chain, find the graded input with both conditions present"; any rule with no graded input that changes is "ungraded ... Fail".
- 03:62 TS-23: "at most 35 (warn)"; 04:89 JD-12 the same; 03:44 TS-13 "One property per test".
- Mechanism: AL-27 multiplies fixtures and tests; the caps push back, but only at warn (tests_qc A3 warns at 36 in the dispatch bundle). Fail vs warn means AL-27 always wins.
- Narrow zone: several triggering fixtures inside one hidden input, each read by its own test (TS-13), and a total above 35 shown to the tasker as a warn.

### Q3. JD-7 vs conduct "constructs its own input" criteria (LEVER_RULES J2), and JD-8 for trap-tracking criteria
- 04:76 JD-7: "Every criterion must be satisfied ... by the shipped oracle in solution/ ... Check EVERY criterion against solve.sh / solve.py line by line." Automatic fail.
- 04:77 JD-8: "Same observable = overlap = fail, regardless of wording. Outcome-vs-process on different observables is fine." Table 04:82 "The response states the correct calibration value | FAIL".
- Mechanism: a criterion such as "The agent notices the stale rate in X" is either an outcome restating the test (JD-8 fail) or a trajectory claim the oracle never exhibits (JD-7 fail, because solve.py does not build probe inputs or log a check). FC:519 confirms no judged oracle score exists, so JD-7 is a reading check of the code.
- Narrow zone: the oracle code really builds the probe case and checks it (then JD-7 passes); the criterion reads the trajectory, not the output (JD-8 passes, 04:84 "artifact behaviour vs derivation method" OK); weight 1 or 3, since JD-15 Step 1 fails (not every competent route builds a probe) and Step 2 makes it odds-raising, "at 5 it is a minor".

### Q4. TS-16 vs anti-hardcoding negatives (AL-10, the 04:62 example)
- 03:47 TS-16: "Anti-cheat negatives must fire on the cheat and ONLY on the cheat. Ask for each: could an honest solution trip this?" 03:135: "fail: ... TS-16 negatives that an honest solution could trip".
- 05:40 AL-10: "The negative tests must catch exactly this." 04:62: "The agent copies a total from /app/data/sample_output.csv into /app/report.json. | -3 | right".
- Mechanism: a negative that fires when the output equals a shipped value trips an honest solution wherever truth equals the shipped value (any L1 green-control row that happens to be right).
- Narrow zone: fire only on cases where the shipped value differs from the truth, preferably on reseeded hidden inputs where a copied value cannot be correct. The cheater-slips-past side of TS-16 has no stated severity (03:135 lists only the honest-trip side).

### Q5. DS-4 / CL-3 vs shipped boundary rows (LEVER_RULES W5)
- 02:20 DS-4: "NO ANSWERS IN DATA - strict, no exceptions"; leak = "a worked example carrying the graded values, a table of expected outputs, a walkthrough that computes a graded result".
- FC:490 CL-3: "Deriving the answer is not this defect and never is".
- Mechanism: a shipped separating row is an input. It becomes a DS-4/CL-3 leak only if a shipped document also states its result.
- Narrow zone: ship the row, never its output (W6 "no worked example where readings differ" already forces this). **The fight is not there as a contradiction; it is a squeeze.**

### Q6. IN-14 vs IN-15 / IN-16 / DS-25 precision
- 01:44 IN-14 fail: "an exact formula handed over when deriving that formula is the work".
- 01:46 IN-16 fails "a rounding or tie-break the contract never settles"; 02:71 DS-25 "Any required literal that appears in no agent-visible file is a fail"; FC:492 CL-5 hidden conventions.
- Mechanism: every reading the contract settles moves it toward a recipe. 01:44 "constraints are expected here, not tolerated" and IN-8's delegation to spec files are the release valve.
- Narrow zone: settle each rule as a definition or constraint in the data file that governs it; never as steps.

### Q7. AL-1 "appears in" vs DS-21 / IN-8 / CL-10 "follows from" (withheld rules)
- 05:21 AL-1 TESTS: "What fails is a test asserting a property that appears in no file the agent can read".
- 02:70 DS-21: "information the agent needs that exists in none of its files and follows from nothing in them"; "Default to pass". 01:38 IN-8 accepts "the shipped data read together with the prompt". FC:498 CL-10 "Derivation counts fully and is meant to". 01:39 IN-9 "Whatever the instruction holds back must still be discoverable from the shipped data, so that a solver can test a guess".
- Mechanism: a rule inferred from data but written nowhere passes DS-21/IN-8/CL-10 and is open to an AL-1 fail by a strict reader who wants it to "appear".
- Narrow zone: the data must let a solver confirm the guess (IN-9), and the review must name the derivation (CL-10 trace). Safer still: one plain sentence in the governing file.

### Q9. TS-19 / AL-2 "every promise graded" vs IN-8 "Do not ask for more than the graded surface" and AL-27

- Narrow zone: state only what is graded; TS-19 lets the judge carry it ("do not demand that a test cover every promise"), except format/shape rules (K1).

### Q10. CL-2 forgery price vs existence/shape tests (TS-27)
- FC:489 CL-2 fails "the forgery reaching the range a genuine partial attempt would earn" and "any test that paid while believing it was grading content". FC:412-420 stub: "never defensible is a stub scoring near the passing range".
- 03:43 TS-27 allows a text check "weighted as existence".
- Narrow zone: few existence or shape tests, at weight 1; report the stub share (FC:489 "The number gets reported either way").

### Q11. CL-6 signposting vs our "never explain a trap" rule (_COMMON_RULES_v2 Never 8, LEVER_RULES W1)
- FC:493 CL-6: every shipped value the truth contradicts must be "signposted as suspect somewhere the agent can read"; "Almost anything does: ... a spec file named as the authority".

- Narrow zone: name the authority (spec over code, rules file over sample) without naming the wrong value. Kit and our rule fit together inside that zone.
