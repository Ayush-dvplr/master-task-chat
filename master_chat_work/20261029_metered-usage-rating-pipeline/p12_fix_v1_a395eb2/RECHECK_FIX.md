## Deviations from master directions

1. G01-1: the master text says "(no fraction, exponent, quotes, bool or null)". The contract now says "written with no fraction or exponent part" only. Quotes, booleans and null are outside "a JSON integer" under both readings the QC named (a JSON Schema integer is also never a string, boolean or null), so naming them settles nothing; naming three or more malformed kinds next to the type is the LV-ENUM pattern precheck.sh:90-109 fails and LEVER_RULES_v3 1b H1 forbids. The added clause covers exactly the two kinds the QC showed are read two ways (12.0, 1e2).
2. G04-1: the master text says each property becomes its own criterion. Three code-quality criteria break LEVER_RULES_v3.md:203 J4 "Exactly one code-quality criterion" and precheck.sh:144-149 (hard gate), and playbook JD-18 says "a list of three conditions fails JD-5". R6 is reduced to the one behavioural act (handlers act on the error). The 150-line and unused-code halves are dropped; no sentence of instruction.md or the contract promises a function length or unused-code rule (G3: nothing rests on them).
3. G05-1: the master text asks for "two inputs from different positions in the list". The new check removes a seeded collector (positions 1-5) and accounts.csv (position 6), which is that case; accounts.csv also sorts before every collector, so an alphabetical loader fails it too. Both asserts live in NEW checks; `_check_missing_collector` is unchanged (G2).
4. G5 vacuity (not a master direction): R10 "lists every file the agent wrote under /app/out" was met by an agent that wrote nothing. It now reads "lists /app/out/transform.py and every other file the agent wrote under /app/out, each by its path." (judge.toml:129-140). Same weight and labels.
