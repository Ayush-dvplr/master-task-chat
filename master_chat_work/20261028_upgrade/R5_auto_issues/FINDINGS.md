The overnight run lost about 32 worker-hours to two silent stalls. Its REPORT noticed only the second one and gave the cause as unknown.

## Lessons for the master

- An opencode session that is busy with no new step for 20+ min is most likely in provider retry. Check `/session/status` for `type: retry` before calling it slow work.
- Start a paid run only in a fresh window and with at most 2-3 workers busy. Preflight "quota OK" says nothing about headroom.
- A watcher alert after one failed check is not an outage. Check `auto.py status` once and move on.
- Never trust an auto-resume time that was not parsed from the provider's reset text.
- In zsh, `set -- ${=x}` splits; `set -- $x` does not.
