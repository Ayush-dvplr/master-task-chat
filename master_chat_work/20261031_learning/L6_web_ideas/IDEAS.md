## Shared design-blind protocol

1. Before authoring a full bundle, give a fresh solver only the draft instruction, copied input, and rule register. Record its first program, its own checks, and whether the submitted program returns a valid but wrong document on three seeded hidden corpora. This follows `LEVER_RULES_v3.md:230-244` and `S5_build_method/FINDINGS.md:9`.
2. For each idea, run the strongest obvious generic solver too. If it is exact and within the published budget, the core has no measured separating power. Classify every loss as WRONG, TIMEOUT, or CRASH; only the narrow hidden-scale exception in `LEVER_RULES_v3.md:86-91` can count timeout/crash.
3. Require a sentence or determinate shipped fact for every graded property (`05_Alignment_Integrity_QC.md:19-21,35`), a trigger fixture for every precedence/tie rule (`:38`), and distinct observables for each rewarded check (`03_Tests_QC.md:52-55`). Never reveal the planted trap in agent-visible prose.
4. Estimate final score from separate test and judge channels. A task that cannot plausibly reach tests <=60 and rubric <=20 is unlikely to make the current <40 gate with margin (`LEVER_RULES_v3.md:85-91`); no idea above has a verified score prediction.
