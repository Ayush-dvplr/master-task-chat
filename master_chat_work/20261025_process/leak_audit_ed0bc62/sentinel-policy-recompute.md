### Root reading (why tests are 100)

Every one of the four counted levers (N1 region allowance, N2 unit cutover, N3 window admit and draw order, N4 pool re-share) is delivered as an executable sentence in the file that holds the governed data, and `tests/test_output.py` is a re-implementation of the same sentences (see `pooled_deltas`, `unit_reader`, the draw loop). The reseeded corpora vary the inputs, not the rules. No step in the trajectory depends on anything but reading the text. Shipped data cannot separate the readings (pool never binds, `rev` coincides with version-before-cutover on all 228 rows), but the text removes the need to see that. The agent wrote the final cli.py in a single `create` at step 33.

The only places the run lost points are the rubric (R6, R7, R10, R12-R16 all 0), whose criteria are invisible: R12-R16 ask for own-ledger checks and the agent only edited the supplied corpus, and R6/R7 ask for running the shipped tool before editing.
